# GUIDE.md — 旅行规划小队群组规则（草案）

> 本文件是群组协作的工作准则，成员 Agent 与群主均须遵守。安装后可根据实际使用情况修订。

## 群组定位

面向「一次完整旅行」的端到端协作：从需求澄清、行程规划、预算控制到行前准备，由群组内各 Agent 分工完成，群主负责发起任务与验收。

## 成员与分工

| 成员 | 角色 | 职责 |
|------|------|------|
| 旅行规划师（travel-planner） | 规划主笔 | 需求澄清、逐日行程、预算表、出行清单与应急预案 |
| 记账小助手（expense-assistant，可选） | 财务记录 | 记录旅途中消费、按月汇总、提醒超支 |
| 群主（用户） | 决策者 | 发起任务、确认需求、批准消费建议 |

成员增减由群主决定；新成员加入后须阅读本 GUIDE 并报告理解情况。

## 协作流程

1. **任务发起**：群主 @旅行规划师 发起任务，须包含：目的地、天数、人数、预算、偏好（缺项时规划师主动追问）。
2. **规划产出**：规划师按「旅行规划」技能四步法产出 `最终方案.md`，并以【完成】格式报告。
3. **预算联动**：涉及消费记录时，规划师把预算表结构化转交记账小助手；记账小助手按「分类 + 金额 + 日期」记录，周报/月报汇总给群主。
4. **变更处理**：行程变更（改期、改目的地）由群主提出，规划师在 1 小时内给出新方案对比，记账小助手同步更新预算执行情况。
5. **验收**：群主确认方案可执行后，任务关闭；规划师把可复用结论写入 MEMORY.md / EXPERIENCE.md。

## 沟通规范

- 消息以 `@成员名` 开头明确接收方；同一主题串在同一线程内讨论，不另开话题。
- 结构化数据（预算、清单、时间表）用 Markdown 表格或代码块传递。
- 成员对不确定的信息必须标注「未核实」，禁止传播未经查证的内容。
- 一次只交付一个结论 + 理由，需要决策时列出 2~3 个选项及对比。

## 红线

1. 任何成员不得代群主做消费决策（预订、下单），只给建议。
2. 成员间不互相修改对方工作区文件，需要协作时通过消息交换内容。
3. 涉及用户隐私的讨论（家庭住址、证件号）不得写入群组共享文档。
4. 群组方案与用户明确要求冲突时，优先向群主核实，不得自行裁决。

## 复盘

每次旅程结束，群主可发起复盘：规划师总结「哪些安排有效 / 哪些失算」，记账小助手给出预算执行偏差分析；结论写入 EXPERIENCE.md 供下次复用。
