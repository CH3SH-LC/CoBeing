# 多 Agent 框架对比调研：CoBeing vs Claude Code / Hermes / OpenClaw / Nanobot

> 调研日期：2026-04-24

---

## 一、各框架定位速览

| 框架 | 一句话定位 | 核心语言 | 成熟度 |
|------|-----------|---------|--------|
| **CoBeing** | 多 Agent 协作框架，Agent 即有完整人格的"同事" | TypeScript (pnpm monorepo) | 开发中 |
| **Claude Code** | Anthropic 官方 CLI 编码 Agent | TypeScript | 生产级 |
| **Hermes** | 自我进化的 AI Agent，闭环学习 | Python (~100K LOC) | 活跃开发 (v0.10) |
| **OpenClaw** | 多渠道 AI 网关，插件生态 | TypeScript (pnpm monorepo) | Beta |
| **Nanobot** | MCP 主机框架，声明式构建 Agent | Go | Alpha |

---

## 二、逐框架架构分析

### 1. Claude Code（Anthropic）

**架构**：单线程 `while(tool_use)` 循环——极简 ReAct 模式。

```
用户输入 → 模型推理 → 产出工具调用？→ 执行工具 → 回到模型
                    → 无工具调用（纯文本）→ 结束，等用户
```

**核心设计**：
- 14 个内置工具（Bash/Read/Write/Edit/Glob/Grep/Web 等）
- 无角色扮演、无人格系统，单一实用型编码 Agent
- 通过 **CLAUDE.md** 四级文件做记忆（企业/项目/用户/本地）
- Haiku 小模型做安全检查（判断是否需要用户审批）

**多 Agent 方案**：
- **Subagent**：`Task` 工具派生子 Agent，独立 context，不能嵌套，结果回传主 Agent
- **Agent Teams**（实验性）：多个 Claude Code 实例，共享 TODO 列表 + 邮箱互发消息
- **手动多实例**：多个终端 + git worktree 隔离

**扩展体系**：
- **Skills**：模型自主调用的能力包（SKILL.md + 资源文件）
- **Plugins**：打包 skills + commands + agents + hooks
- **Hooks**：事件驱动自动化（PreToolUse/PostToolUse/Stop 等）
- **MCP**：外部工具协议接入

**自动化**：无内置调度器，依赖外部 cron 管道 `echo "prompt" | claude -p`

---

### 2. Hermes（Nous Research）

**定位**："随着使用自我进化的 Agent"——唯一主打**闭环学习**的开源框架。

**核心机制——闭环学习**：
```
完成任务 → 自动提取经验 → 打包成 Skill → Skill 随使用被精炼 → 下次任务更快
```
据 Nous Research 基准测试，使用自建 Skill 的 Agent 比全新实例**快 ~40%**。

**架构**：
```
CLI / Gateway(18平台) / ACP(IDE) / Batch / API Server
                    ↓
            AIAgent (run_agent.py) — 核心编排引擎
            ┌─────────────────────────────┐
            │ Prompt Builder │ Provider   │ Tool Registry  │
            │ (SOUL+MEMORY   │ Resolution │ (47 tools,     │
            │  +USER+skills) │ (3 API)    │  19 toolsets)  │
            └─────────────────────────────┘
                 ↓              ↓              ↓
           Compression    Session DB      Tool Backends
           & Caching      (SQLite+FTS5)  (Terminal/Browser/
                                          Web/MCP/File)
```

**多 Agent 现状**：
- `delegate_task`：派生短暂子 Agent，最多 3 个并行，深度限制 2 层，**子 Agent 之间不能通信**
- `mixture_of_agents`：并行查询 4 个模型 + 聚合器，一次性非协作
- **规划中**四阶段进化：工作流 DAG → 容错执行 → Agent 角色池 → 高级模式（对抗辩论、跨平台分发）

**独特功能**：
- FTS5 全文搜索历史会话 + LLM 摘要检索
- Honcho 辩证式用户建模（跨会话构建用户画像）
- Atropos RL 集成（轨迹生成 + 强化学习训练环境）
- 47 工具 / 19 工具集 / 18+ 消息平台适配器
- 内置 cron 调度器（自然语言定时）
- Profile 隔离（同一安装运行多个独立 Agent 实例）

---

### 3. OpenClaw

**定位**：多渠道 AI 网关——把多种 AI 模型连接到多种通讯平台。

**架构**：插件驱动的网关 + 107 个扩展。

```
20+ 通讯渠道 (Slack/Telegram/Discord/QQ/微信/飞书/Teams...)
                    ↓
              Gateway 核心
                    ↓
多 AI 提供商 (OpenAI/Anthropic/Gemini/DeepSeek/Ollama...)
                    ↓
          107 扩展插件 (AI提供商/渠道/工具集成)
```

**核心特点**：
- 不做 Agent 编排，做**管道连接**——把 AI 能力桥接到各种平台
- 插件 SDK + 契约式扩展
- iOS/Android 原生应用
- Lit Web Components 控制面板

**与 Agent 框架的区别**：OpenClaw 是"渠道层"，不是"Agent 层"。它不定义 Agent 人格、不编排多 Agent 协作、不管理工作流。

---

### 4. Nanobot（Obot AI / Darren Shepherd）

**定位**：MCP 主机框架——每个 Agent 都是一个 MCP 服务器。

**核心公式**：`Agent = Model + MCP Servers + MCP-UI 层`

**架构**：声明式/可组合。

```yaml
# nanobot.yaml — 通过配置组合 Agent
agents:
  dealer:
    name: Blackjack Dealer
    model: gpt-4.1
    mcpServers: blackjackmcp

mcpServers:
  blackjackmcp:
    url: https://blackjack.nanobot.ai/mcp
```

也支持 Markdown + YAML frontmatter 定义 Agent：
```markdown
---
name: Shopping Assistant
model: anthropic/claude-3-7-sonnet-latest
mcpServers: [store]
---
You are a helpful shopping assistant.
```

**核心特点**：
- Agent 通过组合 MCP 服务器（工具提供者）来定义，零代码
- MCP-UI 支持富交互组件（表单、按钮、可视化）
- 内置 Web UI + 聊天界面
- LLM "大脑" 与 MCP "身体" 完全解耦
- 多 LLM 提供商支持（OpenAI/Anthropic/Azure/Bedrock/Ollama）

**多 Agent**：多 Agent 定义支持，但健壮协作在路线图上，目前为 Alpha。

## 三、核心维度对比

### Agent 人格与身份

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 人格定义 | 无，单一实用型 Agent | SOUL.md + MEMORY.md + USER.md | 无（网关不定义人格） | YAML frontmatter 中一段 system prompt | **八文件分层人格**（SOUL/CHARACTER/JOB/BOOTSTRAP/TOOLS/EXPERIENCE/MEMORY/USER） |
| 人格持久性 | CLAUDE.md 文件 | SQLite + FTS5 持久化 | 无 | 配置文件持久 | **文件系统持久化，可独立编辑、跨会话演化** |
| 角色深度 | 无角色概念 | SOUL 定义个性 | 不涉及 | 一段 prompt 定义角色 | **像写小说角色——背景故事、怪癖、说话习惯** |
| 成长性 | 无自动学习 | **闭环学习，自动创建/精炼 Skill** | 无 | 无 | **EXPERIENCE + MEMORY + TOOLS 持续积累** |

**CoBeing 差异**：人格粒度最细（8 个独立维度），CHARACTER 要求"像活人"而非"专业助手"。Hermes 的 SOUL.md 最接近，但没有 CoBeing 的分层独立文件体系。

---

### 多 Agent 协作

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 协作模式 | Subagent 派发 + Agent Teams（实验） | delegate_task 派发（规划 DAG） | 不涉及 | 多 Agent 定义，协作在路线图 | **异步事件驱动 + 自发 Agent-to-Agent 交流** |
| Agent 间通信 | Teams 有邮箱系统 | 子 Agent 间不能通信 | 不涉及 | 不涉及 | **主频道 + Talk 子讨论 + @提及唤醒** |
| 编排方式 | 主 Agent 管理 + 共享 TODO | 主 Agent 派发 | 不涉及 | 不涉及 | **Screener 智能过滤 + HostAgent 管理** |
| 群组概念 | 无群组，只有 Teams | 无群组 | 不涉及 | 无群组 | **持久化群组 + 公用 TODO + 独立存储** |

**CoBeing 差异**：唯一将"群组"作为一等公民的框架。Agent 之间可以自发交流（不依赖主 Agent 中转），Talk 子讨论 + 结论回流是独有设计。

---

### 能力扩展策略

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 核心策略 | Skills + Plugins + MCP | 47 工具 + 19 工具集 + MCP | 107 扩展插件 | MCP 服务器组合 | **多 Agent 各自装载专注 Skills** |
| 扩展载体 | 单个 Agent 装更多 Skills | 单个 Agent 装更多工具 | 网关层加插件 | 单个 Agent 组合更多 MCP Server | **一个 Agent = 少量专注 Skills，通过协作覆盖全能力域** |
| 性能影响 | Skills 越多 context 越大 | 工具越多选择越慢 | 插件热插拔无影响 | MCP Server 无关 | **每个 Agent 保持轻量，无单点膨胀** |

**CoBeing 差异**：唯一明确解决"单 Agent 能力膨胀"问题的框架。不是让一个 Agent 变强，而是让一群专注 Agent 协作变强。

---

### 自动化与调度

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 定时机制 | 无内置，外部 cron 管道 | **内置 cron + 自然语言调度** | 无 | 无（Alpha 阶段） | **TODO.json 精准触发（规划中）** |
| 事件系统 | Hooks（PreToolUse/PostToolUse 等） | Hooks + 回调 | 无 | 无 | **Screener 事件驱动** |
| 自主行动 | 需要用户或外部触发 | cron + 技能 + 脚本附加 | 不涉及 | 不涉及 | **TODO 到时自动激活 Agent/群组** |

**CoBeing 差异**：TODO.json 方案 vs Heartbeat 轮询，从"被动轮询"变"主动计划执行"。Hermes 的内置 cron 最成熟，但仍是轮询语义。

---

### 前端与交互

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 界面 | **CLI 为主**（VS Code 扩展） | CLI TUI + 18 平台 Gateway | Web 控制面板 + 原生 App | 内置 Web UI + MCP-UI | **原生桌面应用（Tauri 2.0 + React 19）** |
| 群组视图 | Teams 有（实验性） | 无 | 无 | 无 | **专用群组协作视图** |
| Agent 管理 | CLI 命令 | CLI + Profile | Web 面板 | YAML 配置 | **GUI 直接编辑人格文件 + 管理群组** |

**CoBeing 差异**：唯一提供专用多 Agent 协作 GUI 的框架。其他框架要么 CLI，要么通用聊天 UI。

---

### 记忆与学习

| | Claude Code | Hermes | OpenClaw | Nanobot | **CoBeing** |
|---|---|---|---|---|---|
| 记忆结构 | CLAUDE.md 四级文件 | **三层架构：MemoryStore/Manager/Provider** | 无 | 无（配置持久化） | **八文件中 MEMORY + EXPERIENCE + USER** |
| 跨会话检索 | 无自动检索 | **FTS5 全文搜索 + LLM 摘要** | 无 | 无 | 文件系统直接读取 |
| 自主学习 | 无 | **自动创建/精炼 Skill（闭环学习）** | 无 | 无 | EXPERIENCE 积累 + TOOLS 策略更新 |

**CoBeing 差异**：记忆粒度细（分事件/经验/工具策略），但 Hermes 的闭环学习和 FTS5 检索能力更强。Hermes 是目前唯一真正实现"越用越聪明"的框架。

## 四、CoBeing 的独特价值定位

综合对比后，CoBeing 在以下方面具有不可替代的独特性：

### 1. 群组作为一等公民
其他框架的"多 Agent"都是任务派发模式（主 Agent 分配任务给子 Agent）。CoBeing 的群组是**持久化的协作空间**，Agent 之间自发交流、有独立存储、有公用 TODO。这在所有框架中独一无二。

### 2. 八文件分层人格
Claude Code 不做人格，Hermes 有 SOUL.md 但粒度较粗，Nanobot 只有一段 prompt。CoBeing 的八个独立维度（性格/人物/专长/工具策略/经验/记忆/偏好/诞生知识）提供了最细粒度的 Agent 身份系统。

### 3. Skill 分散装载
所有其他框架的策略都是"给一个 Agent 装更多能力"。CoBeing 的策略是"多个专注 Agent 协作"——从根本上避免了 context 膨胀和指令冲突。

### 4. Screener 智能过滤
Hermes 有类似的智能模型路由（短消息用便宜模型），但 CoBeing 的 Screener 是**群组协作层面的语义过滤**——判断群组讨论是否偏离、是否需要干预，这在其他框架中没有对应物。

### 5. 原生群组协作 GUI
Claude Code 是 CLI，Hermes 是 CLI + Gateway，Nanobot 是通用聊天 UI。CoBeing 是唯一提供**专用多 Agent 协作桌面应用**的框架。

### 6. TODO 驱动自动化
Hermes 有内置 cron（最成熟），但是轮询语义。CoBeing 的 TODO.json 方案是**声明式计划执行**——Agent 写 TODO，程序精准触发，不空转。理念差异：cron 是"定时检查"，TODO 是"到时行动"。

## 五、可借鉴的方向

从其他框架中，CoBeing 可以考虑借鉴：

| 来源 | 借鉴点 | 对 CoBeing 的价值 |
|------|--------|-----------------|
| **Hermes** | 闭环学习（自动从经验创建 Skill） | 让 Agent 不只是积累经验文本，而是自动生成可复用的方法论 |
| **Hermes** | FTS5 全文搜索历史会话 | 增强 MEMORY 的检索能力，不只是文件读取 |
| **Hermes** | Honcho 辩证式用户建模 | 让 USER.md 更智能地演化 |
| **Claude Code** | Subagent 独立 context + 结果回传 | 避免 Agent 间 context 互相污染 |
| **Claude Code** | Hooks 事件系统 | 为 TODO 触发提供更丰富的事件源 |
| **Nanobot** | MCP-UI 富交互组件 | 增强群组协作 GUI 的交互能力 |
| **Nanobot** | 声明式 Agent 定义 | 简化创建流程，降低用户门槛 |
| **OpenClaw** | 多渠道网关架构 | 扩展 CoBeing 的渠道触达能力 |

---

## 六、总结矩阵

| 维度 | 最强者 | CoBeing 位置 |
|------|--------|-------------|
| **Agent 人格深度** | **CoBeing**（八文件分层） | 领先 |
| **多 Agent 协作** | **CoBeing**（自发交流 + 群组） | 领先 |
| **自主学习** | **Hermes**（闭环学习） | 需要加强 |
| **记忆检索** | **Hermes**（FTS5 + LLM 摘要） | 需要加强 |
| **自动化调度** | **Hermes**（内置 cron）→ **CoBeing**（TODO.json 规划中） | 规划中有独特理念 |
| **工具/能力生态** | **Claude Code**（14 工具 + MCP + Skills + Plugins） | 通过多 Agent 协作互补 |
| **渠道覆盖** | **Hermes**（18+ 平台）/ **OpenClaw**（20+ 渠道） | 有多渠道绑定，但需扩展 |
| **前端体验** | **CoBeing**（原生群组协作 GUI） | 领先 |
| **声明式易用性** | **Nanobot**（YAML 零代码） | 可借鉴 |
| **成熟度/稳定性** | **Claude Code**（生产级） | 开发中 |
