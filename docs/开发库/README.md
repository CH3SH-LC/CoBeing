# CoBeing 开发库

> 建立：2026-08-12（重构：2026-08-12，进度.md → 功能清单.md）
> 定位：CoBeing 的独立开发追踪库——核心维护**功能清单**（哪些功能做了），配套「计划 / 想法」两块；**进度日志（每次改了什么）属于 `PROGRESS.md`，不在本库维护**。

---

## 这个库管什么

| 文件 | 内容 | 更新时机 |
| --- | --- | --- |
| `功能清单.md` | **核心**：哪些功能做了——12 能力域功能清单 + 完成状态（✅/🚧/📌）+ 统计 | 功能落地 / 状态变化时 |
| `计划.md` | 有什么开发计划——近期进行中、待办、路线图 | 计划变化时 |
| `想法.md` | 有什么想法——点子、构想、待验证假设 | 随时追加 |

三块互相链接，也回链到权威文档（`PROGRESS.md`、`当前待办.md`、`项目现状.md` 等）。

---

## 与现有文档的分工

| 文档 | 角色 | 本库不重复 |
| --- | --- | --- |
| `PROGRESS.md` / `PROGRESS-LITE.md` | 每次代码变更的强制记录（详细 + 速查） | 逐条变更日志 / 进度 |
| `docs/项目信息/项目现状.md` | 按代码事实的当前实现与边界 | 能力边界详述 |
| `docs/项目信息/当前待办.md` | 仍有效的待办 + 决策记录 | 待办原始清单 |
| `docs/项目信息/产品战略.md` | 产品定位与战略共识 | 战略论述 |
| `docs/项目信息/最新版总览.md` | v1.4.0 全项目一次性盘点 | 静态总览 |
| **本库** | **持续维护的功能清单（哪些做了）+ 计划 + 想法** | 权威事实全量照搬 |

> 原则：**权威事实不重复维护**。功能清单是「打勾视图」——一眼看出哪些功能做了、哪些没有；细节引向 `项目现状.md`、`当前待办.md`、`PROGRESS.md`。

---

## 更新约定

1. **功能落地** → 在 `功能清单.md` 对应域新增/勾选 ✅（备注版本/日期），同步更新统计表；进度日志照旧写入 `PROGRESS.md`。
2. **新计划 / 计划变更** → 更新 `计划.md`，保持与 `当前待办.md` 同步。
3. **新想法** → 随时在 `想法.md` 追加；成熟为计划移入 `计划.md`，落地后在 `功能清单.md` 勾选 ✅。
4. 内容必须与代码实际状态一致，不得有幻觉。
