## 产品想法

- **管家入口作为唯一默认入口**（源自 `产品战略.md` / 决策 #11）：GUI 默认只露「管家 + 设置」，其余收进「⋯」菜单。待验证：普通用户是否真的只靠管家就能办成事，进阶入口是否成了噪声。→ 已部分落地（NavBar 折叠），效果待真实用户验证。
- **初次使用对话式收集**（替代问卷，2026-08-05 已落地）：收集兴趣/称呼/相处方式 → 创建 1-2 初始 Agent → 轻量推荐。待验证：收集的信息是否足以产出贴合需求的 Agent。
- **「超级个体」体验靠生活场景闭环证明**：旅行 / 学习陪伴 / 家庭事务 / 内容创作 / 个人研究 五个场景，验证「管家能不能低摩擦接住需求」。

## 产品技术边界待补（开放问题）

- **Market 走向完整**：certified 官方认证审核流程怎么定义？认证远程市场仓库结构？persona / plugin 资源如何进入安装链路？社区资源如何做版本更新与安全修复？→ 均见 `当前待办.md` P0。
- **「真实软件接入」方向再走多远**：浏览器 MCP（真实网页操作）+ QQ 已让 Agent 触达真实世界。下一步可探索：更安全的浏览器会话复用边界、更多真实软件通道。
- **管家「应派发」从软纪律到硬约束**：执行工具已结构性移除（决策 #1），但管家行为仍靠 prompt 纪律，LLM 方差仍可能「亲自上手」。可继续让约束更结构化。
- **群组多 Agent 并发**：并发写靠 CAS 防护、群组单一推进者靠纪律。自研编排是否真要支持高并发，还是收敛为「路由 + 串行推进」？需持续按真实场景判断。
