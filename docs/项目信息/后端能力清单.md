## 一、Agent 系统

### 1.1 Agent 基类 (`agent.ts`)

| 能力 | 说明 |
|------|------|
| 生命周期管理 | idle → running → idle 状态切换 |
| 多会话 | 每个 channel+sender 独立 ConversationLoop (`sessionLoops`) |
| 消息处理 | `handleIncomingMessage()` 接收 Channel/GUI 消息 |
| 直接运行 | `run()` 模式用于测试和 GUI |
| 工具执行 | 通过 ToolExecutor 调用已注册工具 |
| LLM 调用 | 通过 LLMGateway 请求 Provider |

### 1.2 自治文件系统 (`paths.ts`)

每个 Agent 拥有独立目录 `data/agents/{id}/`：

| 文件 | 用途 | 读写方 |
|------|------|--------|
| `CHARACTER.md` | 性格特征 | Agent 自我更新 / 管家创建时写入 |
| `JOB.md` | 工作职责描述 | Agent 自我更新 |
| `SOUL.md` | 灵魂/人格，追加到 system prompt 最前面 | Agent 自我更新 |
| `USER.md` | 用户偏好和画像 | 用户编辑 / Agent 学习 |
| `BOOTSTRAP.md` | 启动引导，首次激活时读取后自动删除 | 管家创建时写入 |
| `AGENTS.md` | 工作空间指南：行为准则 | 框架模板 + Agent 完善 |
| `EXPERIENCE.md` | 经验积累（问题-解决方案对） | 自动反思写入 |
| `config.json` | 运行时配置 (provider/model/permissions/tools/skills) | 管家创建 / 用户编辑 |
| `memory/` | 每日记忆 `YYYY-MM-DD.md` | MemoryWriter 自动写入 |

### 1.3 System Prompt 构建链 (`prompt-builder.ts`)

按固定顺序从文件组装，不硬编码：
```
SOUL.md → BOOTSTRAP.md(一次性) → systemPrompt(role) → AGENTS.md → USER.md → EXPERIENCE.md
```

- BOOTSTRAP.md 读取后自动删除
- EXPERIENCE.md 跳过短内容 (<50 字符)

### 1.4 ButlerAgent 管家 (`butler.ts`)

特权 Agent，拥有 full-access 权限，注册 14 个工具（System Prompt 含多步推理 + 主动建议指南）：

| 分类 | 工具 | 功能 |
|------|------|------|
| Agent 管理 | `butler-create-agent` | 创建新 Agent，写入 config.json + 模板 |
| | `butler-destroy-agent` | 销毁指定 Agent |
| 群组管理 | `butler-create-group` | 创建群组 |
| | `butler-destroy-group` | 销毁群组 |
| | `butler-list` | 列出所有 Agent（含运行状态）和群组 |
| | `butler-run-group` | 启动群组协作 |
| | `butler-add-to-group` | 添加成员到群组 |
| | `butler-check-group` | 检查群组进展（PROGRESS.md + TODO + 成员） |
| 注册表 | `butler-read-registry` | 读取注册表 |
| | `butler-update-registry` | 更新注册表 |
| Channel | `channel-bind` | 绑定 Channel 到 Group |
| | `channel-unbind` | 解绑 Channel |
| 工作流 | `workflow-analyze` | 分析任务 |
| | `workflow-plan` | 生成执行计划 |

> 注：`talk-create`/`talk-send`/`talk-read`/`group-members` 等群组通信工具注册在 `group-tools.ts` 中，供所有 Agent 使用，非 Butler 专属。

### 1.5 AgentRegistry (`registry.ts`)

全局注册中心：`register()` / `get()` / `list()` / `unregister()`，注册时检查 ID 唯一性。

### 1.6 SubAgentSpawner (`spawner.ts`)

动态创建临时子 Agent，继承父 Agent 的 provider 和工作目录。

### 1.7 HostAgent 群主

预置基本智能体（不是每群组创建一个），在 `config/default.json` 的 agents 数组中配置，runtime 启动时注册。创建群组时自动加入为 owner。

## 二、群组与协作系统

### 2.1 Group (`group.ts`)

项目工作组（非讨论组），长期存在：

| API | 功能 |
|-----|------|
| `postMessage(fromId, content)` | 发消息到 main 频道 |
| `createTalk(members, topic)` | 创建私有讨论 |
| `postToTalk(talkId, fromId, content)` | 向 talk 发消息 |
| `postTalkSummary(fromId, talkId, summary)` | talk 结论摘要发回 main |
| `wakeAgent(agentId)` | 手动唤醒 Agent |

### 2.2 GroupContextV2 (`group-context-v2.ts`)

tag-based 统一消息数组：

```typescript
interface GroupMessageV2 {
  id: string;
  tag: "main" | string;    // "main" 或 "talk-001"
  fromAgentId: string;
  content: string;
  timestamp: number;
  mentions: string[];       // @mention 列表
}
```

- main 消息：所有成员可见
- talk 消息：只有参与者可见
- `buildContextFor(agentId)` — 为指定 Agent 构建过滤后上下文

### 2.3 WakeSystem (`wake-system.ts`)

事件驱动唤醒队列，无轮次概念：
```
新消息 → 扫描 @mentions → 加入唤醒队列 → 逐个唤醒 Agent → 回复写回上下文 → 检查新 mentions
```

### 2.4 Screener (`screener.ts`)

群主双模型初筛：
- 轻量级模型，每条新消息触发
- 不执行工具，只判断是否需要唤醒主模型
- 输出格式固定便于解析

### 2.5 ChannelRouter (`router.ts`)

Channel 消息到 Group 的路由：
- **user 模式**: 消息注入 main 频道
- **owner 模式**: 消息注入持久 Talk
- 支持动态绑定/解绑 + 静态配置加载

### 2.6 GroupWorkspace (`workspace.ts`)

每个群组独立工作空间 `data/groups/{id}/`，7 个 Markdown 文档：

| 文件 | 用途 |
|------|------|
| `MEMBERS.md` | 成员列表和职责 |
| `STRUCTURE.md` | 项目结构 |
| `TASK.md` | 任务描述和验收标准 |
| `PROGRESS.md` | 当前进度和完成情况 |
| `PLAN.md` | 任务分工和执行计划 |
| `GUIDE.md` | 群组规则（协作约定/工作流约束/沟通规范），Agent 群组对话时自动注入 system prompt（前 4000 字符） |
| `EXPERIENCE.md` | 群组经验积累（问题-解决方案对），含摘要索引 |

### 2.7 群组持久化 + 生命周期

- `GroupManager.saveGroup()` + `restoreGroups()`
- 群组存储在 `data/groups/{id}/config.json`，含 `status` 字段
- **状态机**: `active` → `completed`（Scanner 检测 TODO 全完成 + 静默>1h 自动标记）→ `archived`（手动触发，zip 打包到 `data/archives/`）
- **冻结规则**: completed 拒绝消息/TODO 只读；archived 完全冻结并从内存移除
- **恢复**: `restoreGroup()` 解压 zip → 重建 Group + Scanner
- ButlerRegistry 维护 `AGENTS_REGISTRY.md` + `GROUPS_REGISTRY.md`
- Runtime 启动时扫描恢复

## 三、Skill 技能系统

### 3.1 SkillRepository (`repository.ts`)

统一技能仓库，SKILL.md 格式：

| API | 功能 |
|-----|------|
| `list()` | 列出所有技能 |
| `get(name)` | 获取指定技能 |
| `create(name, desc, prompt)` | 创建新技能 |
| `search(keyword)` | 关键词搜索 |
| `execute(name, task, params)` | 执行技能 |

### 3.2 统一工具 (`skill-tools.ts`)

| 工具 | 参数 | 说明 |
|------|------|------|
| `skill-execute` | name, task, params? | 执行技能，受 config.json skills 白名单限制 |
| `skill-list` | 无 | 列出可用技能（白名单过滤后） |
| `skill-create` | name, description, prompt | 在仓库中创建新技能 |

### 3.3 内置技能

| 技能 | 目录 | 说明 |
|------|------|------|
| `code-review` | `skills/code-review/` | 代码审查 (质量/安全/性能/最佳实践) |
| `project-planning` | `skills/project-planning/` | 项目规划 (需求分析/任务分解/风险评估) |
| `group-coordination` | `skills/group-coordination/` | 群组协调 (引导讨论/任务委托/冲突处理/进度监控) |

## 七、记忆与经验系统

### 7.1 MemoryStore 统一记忆引擎 (`memory/memory-store.ts`)

四个目标：`memory` / `experience` / `user` / `tools`（对应 MEMORY.md / EXPERIENCE.md / USER.md / TOOLS.md）

| 能力 | 说明 |
|------|------|
| 双存储 | Markdown（权威）+ SQLite FTS5（搜索索引） |
| 冻结快照 | 会话开始时捕获快照，会话内 system prompt 不随写入变化 |
| 安全扫描 | 写入前检测 prompt 注入 / 数据泄露 / 隐形字符 |
| 原子写入 | 临时文件 + rename 替代 appendFileSync |
| 字符限制 | 每个目标独立上限，超限时需合并或删除旧条目 |
| 全文搜索 | SQLite FTS5 全文索引，支持 target 过滤和 limit |
| 信任反馈 | markHelpful / markUnhelpful / adjustTrust 按条目调整信任分数 |
| 自动推理 | 重复条目自动降分、反思时关联经验自动加分 |
| searchAndFeedback | 搜索并标记条目（组合搜索+反馈操作） |

### 7.2 记忆工具 (`memory/memory-tool.ts`)

Agent 通过 `memory` 工具自主管理记忆，支持四种操作：

| 操作 | 说明 |
|------|------|
| `add` | 新增条目，带安全检查和容量验证 |
| `replace` | 用 `old_text` 定位并替换已有条目 |
| `remove` | 用 `old_text` 定位并删除条目 |
| `read` | 查看指定目标的全部内容 |

### 7.3 经验系统 (`memory/experience.ts`)

- `append(entry)` — 手动追加经验
- `reflect(task, conversation)` — LLM 自动反思提取经验
  - 只在有工具调用时触发（跳过闲聊）
  - 质量过滤: problem/solution < 10 字跳过
  - Prompt 从 `prompts/experience-reflect.md` 读取
- `search(keyword)` — 关键词搜索相关经验

### 7.4 兼容模块

| 模块 | 文件 | 功能 |
|------|------|------|
| MemoryWriter | `memory/writer.ts` | 每日对话原始记录写入 `memory/YYYY-MM-DD.md`（保留兼容） |
| MemoryReader | `memory/reader.ts` | 关键词搜索（保留兼容） |
| MemoryIndexer | `memory/indexer.ts` | LLM 总结索引（保留兼容） |

### 7.5 事件总线 (`agent/event-bus.ts`)

事件类型: `group-message` / `agent-direct` / `task-complete`。Agent 订阅总线接收自发消息。

## 十二、运行时 (`runtime.ts`)

CoBeingRuntime 顶层编排器启动流程：
1. 构建多 Provider (9 家)
2. 创建全局 SkillRepository
3. 创建 ButlerAgent + HostAgent
4. 注入 SkillRepository 到所有 Agent
5. 创建 GroupManager + ChannelRouter
6. `start()`:
   - 恢复已持久化的 Agent (从 config.json)
   - 注入 SkillRepository
   - 连接 ChannelRouter → Butler
   - 加载静态 Channel 绑定
   - 启动 WebSocket Server
   - 启动所有 Channel

## 十三、可观测性 (`observability/observability-db.ts`)

| 能力 | 说明 |
|------|------|
| LLM 调用日志 | 每次 LLM 调用记录 model、provider、latency、tokens、错误信息、降级状态 |

| WS 命令 | `get_dashboard` / `get_llm_stats` / `get_tool_stats` 3 个查询命令 |

**数据表**：
- `llm_calls` — 15 字段，含 agent_id、model、provider、latency_ms、tokens、is_error、fallback_used

**注入链**: Runtime 创建单例 → butler / restored agents / prebuilt agents → ConversationLoop + ToolExecutor
