# CoBeing 使用说明

> 最后更新：2026-08-09  
> 适用于当前代码状态，不包含旧版已删除文档中的过时能力。

---

## 环境要求

- Node.js >= 22
- pnpm >= 10
- Rust：桌面 Tauri 模式需要
- Docker：沙箱功能需要，不安装也可以运行基础能力
- 至少一个 LLM API Key：默认建议先配置 DeepSeek

---

## 启动项目

### 1. 安装依赖

在工作区根目录执行：

```bash
cd CoBeing
pnpm install
```

### 2. 配置环境变量

复制环境变量模板：

```bash
cp .env.example .env
```

至少配置：

```env
DEEPSEEK_API_KEY=your_key_here
```

默认配置中只启用 DeepSeek。其他 Provider 主要通过插件数据扩展，不应假设全部默认可用。

### 3. 启动

Windows 可以使用：

```bash
start.bat
```

也可以在 `CoBeing/` 目录执行：

```bash
pnpm dev
```

浏览器模式通常打开：

```text
http://localhost:1420
```

> 2026-08-04 起浏览器模式完全可用：此前 `useTray` 直接调用 Tauri API（`getCurrentWindow`）在非 Tauri 环境抛错导致 React 启动崩溃白屏，已新增 `isTauri()` 守卫（`gui-v2/src/lib/utils.ts`），浏览器模式与无头测试环境均可正常渲染。若用浏览器打开页面为空白，请确认前端已重新构建（`pnpm build`）。

后端 GUI WebSocket 默认监听：

```text
ws://127.0.0.1:18765
```

桌面 Tauri 模式需要进入 `gui-v2` 并启动 Tauri 开发环境，具体以当前 `gui-v2` 配置为准。

## 普通用户怎么使用

### 1. 从管家开始

管家是默认入口。你可以像聊天一样提出需求，例如：

- 帮我创建一个擅长旅行规划的 Agent。
- 帮我组建一个写作群组。
- 帮我查看现在有哪些智能体。
- 帮我给某个 Agent 修改说话风格。
- 帮我把这个任务交给一个群组处理。

管家的价值在于把 Agent、Group、工具和扩展隐藏在对话背后，让普通用户不必先理解系统结构。

**导航（2026-08-09 GUI 入口收敛）**：顶部导航栏默认只显示**管家**和**设置**两个入口，其余（智能体/群组/仪表盘/扩展）收进「⋯」菜单；进阶用户可在 `设置 → 常规 → 完整导航` 打开开关恢复全量入口（选择会记住）。

**首次使用**：第一次启动会先出现 6 步概念教程，关闭后管家会在聊天窗口主动打招呼，**通过对话收集你的信息**（最近想解决的事、希望管家怎么称呼你、喜欢什么样的相处方式），并根据你的回答：按喜好调整管家形象（人格模板切换/称呼记录）、创建 1-2 个贴合需求的初始智能体、轻量推荐官方资源（每会话 ≤1 次）。全程没有问卷弹窗，像和真人聊天一样完成初次设置。也可以直接跳过这些话题，先让管家办正事。

**任务转接**：把任务交给管家后，聊天里会出现任务回执卡片（运行中/待确认/已完成等状态，可展开看摘要与下一步），左侧全局任务面板同步显示进度；派发任务给哪个智能体/群组，也可以直接在输入框上方的「派发」菜单里选。

**管家形象**：在管家页右上角设置里可以改管家的称呼、欢迎语，或在 4 个人格模板（亲密朋友/专业秘书/学习陪伴/家庭助理）之间切换——管家会按模板改变说话方式。

### 2. 使用独立 Agent

Agent 适合处理稳定、可复用、个性明确的任务，例如：

- 旅行规划
- 写作陪伴
- 学习辅导
- 资料整理
- 代码审查
- 日程提醒

每个 Agent 都有自己的职责、模型、工具、权限和记忆。执行型智能体**不再拥有独立角色/人设**（无 CHARACTER.md），只有「表达规范」（EXPRESSION.md）——像真人同事一样说话（短句、结论先行、不客服腔），但不扮演任何身份；管家（Butler）保留人格形象（CHARACTER.md，4 种人格模板可切换）。进阶用户可以直接编辑 Agent 的 `EXPRESSION.md`（怎么说）和 `JOB.md`（怎么做），普通用户则可以通过管家让系统代改。

### 3. 使用群组

Group 适合多角色协作任务，例如：

- 一个主持人拆任务
- 一个研究员收集资料
- 一个写作者产出草稿
- 一个审查者检查问题

群组消息中可以 @mention 成员，被 @ 的 Agent 会进入唤醒队列并处理上下文。

**用户参与群组**：智能体在群组内 `@用户`（@用户 / @主人 / @老板 / @user）时会唤醒你（系统通知 + 未读徽章），你可以直接在群组聊天里回复，参与确认和决策；平时智能体互相协作**不会打扰你**（无通知、不计未读）。需要你做决策时，也可以由管家把群组结果收束到管家窗口给你确认。

进阶用户可以直接进入群组工作区和群组聊天；普通用户更适合让管家创建和调度群组。

### 4. 使用扩展

扩展页当前包含：

- Skills：浏览、搜索、创建技能，切换 Agent 技能白名单
- MCPs：添加、编辑、删除 MCP server 配置
- Plugins：启用/禁用插件，编辑插件配置，查看模型信息
- Market：按信任分级浏览与安装资源（官方内置/官方认证/社区/本地私有）

扩展页更适合进阶用户。普通用户理想路径应该是由管家根据需求推荐或创建扩展，而不是自己在 market 中大量筛选。

### 5. 使用 Market

Market 是「可信能力供应链」，不是普通用户主入口。它提供：

- **分层浏览**：官方内置（随应用打包、默认可信）、官方认证（预留层）、社区（未审核，必须人工确认）、本地私有（你自己创建或安装过的 Agent/技能自动聚合）。
- **依赖树透明**：查看资源详情时显示完整依赖链（如群组 → 智能体 → 技能），安装前即可确认会连带安装什么。
- **安装规则**：官方/认证资源一键安装；社区资源会弹出确认区，提示「来自社区、未经过官方审核」，确认后才安装；本地资源不可安装（已存在）。
- **卸载**：已安装资源可卸载（依赖不级联卸载）。
- **管家推荐**：可以请管家帮忙找资源——管家会优先推荐官方/认证资源，社区资源会明确标注需要你审查。

### 6. 设置个人资料和主题

在设置 -> 个人资料中，可以设置你在聊天气泡里显示的昵称和头像。头像支持首字、Emoji 或图片 URL/data URL；保存后，单聊和群聊中的用户消息会显示该昵称和右侧头像，智能体消息显示在左侧。

在设置 -> 主题中，可以切换樱花薄荷、工作台等主题。默认樱花薄荷主题采用浅樱粉/薄荷渐变背景、奶白半透明面板和糖果感聊天气泡。聊天气泡颜色会随当前主题变化；如果导入自定义主题，需要包含 `chat.msg-user`、`chat.msg-assistant`、`chat.msg-system`、`chat.msg-tool`。

## 进阶用户怎么使用

### 修改 Agent 的表达与工作方式

当前最重要的两个文件是：

- `EXPRESSION.md`：决定 Agent 怎么说——篇幅、句式、禁语、真人信号（人味表达规范，**无身份设定**；2026-08-05 起取代 CHARACTER.md）
- `JOB.md`：决定这个 Agent 怎么思考、怎么工作、如何判断质量

如果要改“像真人同事说话还是像客服”，优先改 `EXPRESSION.md`。如果要改“如何完成旅行规划/代码审查/写作”，优先改 `JOB.md`。管家（Butler）是唯一保留 `CHARACTER.md` 人格的入口（亲密朋友/专业秘书等 4 人格模板，见「管家形象」设置）。

### 管理工具和权限

Agent 的工具和权限在 `config.json` 中控制，也可以通过 GUI 配置页操作。

权限会影响后端真实工具执行，不只是前端显示。因此给 Agent 开 bash、文件写入、MCP 等能力时，需要考虑安全边界。

### 管理群组工作区

群组有自己的工作区文件和消息上下文。它更像一个长期项目空间，而不是一次性聊天窗口。

适合把复杂任务拆成：

- 目标
- 成员分工
- 计划
- 进度
- 交付物
- 复盘经验

### 配置 MCP

默认配置中 `claude-code` MCP server 已自动接入（`claude_code_start/status/result/cancel/list` 五个工具），其余 server 需在扩展页或配置中添加。

**让 Agent 使用 Claude Code 编码能力**（2026-08-11）：Agent 在对话中调 `mcp-discover` 查看、`mcp-register serverId="claude-code"` 注册工具后，即可用 `claude_code_start` 把编码任务（如"修复 X bug + 跑测试"）委托给 Claude Code 完整 agent 循环执行——它自己读写文件、跑命令、多轮修 bug，返回真实结果。`claude_code_result` 轮询等待（受单次工具调用 ~25s 上限，可反复调）。延续上下文传上次结果里的 `session_id`。

**注意**：`working_dir` 必须是存在的绝对路径；默认 bypassPermissions 下工作目录是会话根目录而非写 jail，委托的任务会真实改动文件（含目录外绝对路径），请按可信任务使用。

当前 MCP 基础设施存在，但 discover/register 链路仍建议逐项验证。遇到 MCP 工具不可用时，优先检查：

- server 是否配置
- server 是否启动
- stdio/http transport 是否匹配
- Agent 工具白名单是否允许
- 后端日志是否有注册错误

## 当前使用边界

以下能力不要按成熟产品能力理解：

- Market 分级安装体验已落地（官方/社区/本地分层 + 依赖树 + 社区确认门禁），但官方认证审核流程、认证远程市场、社区资源版本更新与安全修复机制尚未实现；persona/plugin 资源暂不能通过 Market 安装。
- 管家自动判断 market 扩展质量的规则已有工具基础（butler-market-recommend），但推荐评分与阈值策略还需产品化。
- 部分插件 hook、prompt layer、MCP discover/register 需要端到端验证。
- 沙箱监控中的部分指标可能是占位。
- 扩展页的个别操作可能只完成配置展示，还需要确认真实执行链路。

## 推荐使用路径

### 初次使用

1. 配置 DeepSeek API Key。
2. 启动 GUI。
3. 先和 Butler 对话。
4. 让 Butler 创建一个与你真实需求相关的 Agent。
5. 用这个 Agent 完成一个小任务。
6. 如果任务复杂，再让 Butler 创建 Group。

### 产品化后的理想路径

未来面向普通用户时，更合理的路径应该是：

1. 首次启动询问用户需求和偏好。
2. 管家根据需求创建初始 Agent。
3. 如果官方认证 market 中有明显更好的 Agent/Group/Skill/Plugin，再轻量提示用户安装。
4. 未认证社区扩展必须由用户主动审查后授权。
5. 用户日常只和管家或常用 Agent/Group 对话，不需要频繁浏览 market。

## 2026-06-12 GUI 使用与视觉说明

当前 GUI 的顶部条和最左侧导航栏保持固定。进入管家、智能体、群组等主体页面后，页面右侧主体区域分为：
- 左侧列表卡片：管家页显示全局任务，智能体页显示 Agent 列表，群组页显示群组列表。
- 上侧标题卡片：显示当前对象名称、状态、模型/成员数、连接状态和设置按钮。
- 主体对话卡片：上方为对话消息区，下方为输入区。

点击标题卡片中的设置按钮会打开最上层设置浮层；浮层打开时，底层内容会显示磨砂遮罩。智能体设置、群组设置和管家配置都使用同一套浮层规则。

用户可以在设置页的个人资料中配置昵称和头像。对话气泡中用户消息显示昵称和右侧头像；智能体或群组成员消息显示在左侧。气泡颜色由当前主题控制，默认主题为 Sakura Mint，另有 Executive Workbench 作为工作台主题保留。

新手教程重新打开时，也会使用同一套磨砂浮层和主题化卡片外观。
