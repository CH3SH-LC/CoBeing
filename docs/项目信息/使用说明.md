# CoBeing 使用说明

> 最后更新：2026-06-12  
> 适用于当前代码状态，不包含旧版已删除文档中的过时能力。

---

## 环境要求

- Node.js >= 22
- pnpm >= 10
- Rust：桌面 Tauri 模式需要
- Docker：沙箱功能需要，不安装也可以运行基础能力
- 至少一个 LLM API Key：默认建议先配置 DeepSeek

---

## 启动项目

### 1. 安装依赖

在工作区根目录执行：

```bash
cd CoBeing
pnpm install
```

### 2. 配置环境变量

复制环境变量模板：

```bash
cp .env.example .env
```

至少配置：

```env
DEEPSEEK_API_KEY=your_key_here
```

默认配置中只启用 DeepSeek。其他 Provider 主要通过插件数据扩展，不应假设全部默认可用。

### 3. 启动

Windows 可以使用：

```bash
start.bat
```

也可以在 `CoBeing/` 目录执行：

```bash
pnpm dev
```

浏览器模式通常打开：

```text
http://localhost:1420
```

后端 GUI WebSocket 默认监听：

```text
ws://127.0.0.1:18765
```

桌面 Tauri 模式需要进入 `gui-v2` 并启动 Tauri 开发环境，具体以当前 `gui-v2` 配置为准。

## 普通用户怎么使用

### 1. 从管家开始

管家是默认入口。你可以像聊天一样提出需求，例如：

- 帮我创建一个擅长旅行规划的 Agent。
- 帮我组建一个写作群组。
- 帮我查看现在有哪些智能体。
- 帮我给某个 Agent 修改说话风格。
- 帮我把这个任务交给一个群组处理。

管家的价值在于把 Agent、Group、工具和扩展隐藏在对话背后，让普通用户不必先理解系统结构。

### 2. 使用独立 Agent

Agent 适合处理稳定、可复用、个性明确的任务，例如：

- 旅行规划
- 写作陪伴
- 学习辅导
- 资料整理
- 代码审查
- 日程提醒

每个 Agent 都有自己的角色、职责、模型、工具、权限和记忆。进阶用户可以直接编辑 Agent 的 `CHARACTER.md` 和 `JOB.md`，普通用户则可以通过管家让系统代改。

### 3. 使用群组

Group 适合多角色协作任务，例如：

- 一个主持人拆任务
- 一个研究员收集资料
- 一个写作者产出草稿
- 一个审查者检查问题

群组消息中可以 @mention 成员，被 @ 的 Agent 会进入唤醒队列并处理上下文。

进阶用户可以直接进入群组工作区和群组聊天；普通用户更适合让管家创建和调度群组。

### 4. 使用扩展

扩展页当前包含：

- Skills：浏览、搜索、创建技能，切换 Agent 技能白名单
- MCPs：添加、编辑、删除 MCP server 配置
- Plugins：启用/禁用插件，编辑插件配置，查看模型信息

扩展页更适合进阶用户。普通用户理想路径应该是由管家根据需求推荐或创建扩展，而不是自己在 market 中大量筛选。

### 5. 设置个人资料和主题

在设置 -> 个人资料中，可以设置你在聊天气泡里显示的昵称和头像。头像支持首字、Emoji 或图片 URL/data URL；保存后，单聊和群聊中的用户消息会显示该昵称和右侧头像，智能体消息显示在左侧。

在设置 -> 主题中，可以切换樱花薄荷、工作台等主题。默认樱花薄荷主题采用浅樱粉/薄荷渐变背景、奶白半透明面板和糖果感聊天气泡。聊天气泡颜色会随当前主题变化；如果导入自定义主题，需要包含 `chat.msg-user`、`chat.msg-assistant`、`chat.msg-system`、`chat.msg-tool`。

## 进阶用户怎么使用

### 修改 Agent 个性

当前最重要的两个文件是：

- `CHARACTER.md`：决定这个 Agent 像谁、怎么说话、有什么语言风格
- `JOB.md`：决定这个 Agent 怎么思考、怎么工作、如何判断质量

如果要改“像一个亲密朋友还是专业秘书”，优先改 `CHARACTER.md`。如果要改“如何完成旅行规划/代码审查/写作”，优先改 `JOB.md`。

### 管理工具和权限

Agent 的工具和权限在 `config.json` 中控制，也可以通过 GUI 配置页操作。

权限会影响后端真实工具执行，不只是前端显示。因此给 Agent 开 bash、文件写入、MCP 等能力时，需要考虑安全边界。

### 管理群组工作区

群组有自己的工作区文件和消息上下文。它更像一个长期项目空间，而不是一次性聊天窗口。

适合把复杂任务拆成：

- 目标
- 成员分工
- 计划
- 进度
- 交付物
- 复盘经验

### 配置 MCP

MCP server 默认不会自动接入。需要在扩展页或配置中添加 server 信息。

当前 MCP 基础设施存在，但 discover/register 链路仍建议逐项验证。遇到 MCP 工具不可用时，优先检查：

- server 是否配置
- server 是否启动
- stdio/http transport 是否匹配
- Agent 工具白名单是否允许
- 后端日志是否有注册错误

## 当前使用边界

以下能力不要按成熟产品能力理解：

- Market 官方认证和社区分级还没有完整产品化。
- 管家自动判断 market 扩展质量的规则还需要设计和实现。
- 部分插件 hook、prompt layer、MCP discover/register 需要端到端验证。
- 投票、仲裁、复杂依赖协作有底层结构，但 GUI 和默认链路不完整。
- 沙箱监控中的部分指标可能是占位。
- 扩展页的个别操作可能只完成配置展示，还需要确认真实执行链路。

## 推荐使用路径

### 初次使用

1. 配置 DeepSeek API Key。
2. 启动 GUI。
3. 先和 Butler 对话。
4. 让 Butler 创建一个与你真实需求相关的 Agent。
5. 用这个 Agent 完成一个小任务。
6. 如果任务复杂，再让 Butler 创建 Group。

### 产品化后的理想路径

未来面向普通用户时，更合理的路径应该是：

1. 首次启动询问用户需求和偏好。
2. 管家根据需求创建初始 Agent。
3. 如果官方认证 market 中有明显更好的 Agent/Group/Skill/Plugin，再轻量提示用户安装。
4. 未认证社区扩展必须由用户主动审查后授权。
5. 用户日常只和管家或常用 Agent/Group 对话，不需要频繁浏览 market。

## 2026-06-12 GUI 使用与视觉说明

当前 GUI 的顶部条和最左侧导航栏保持固定。进入管家、智能体、群组等主体页面后，页面右侧主体区域分为：
- 左侧列表卡片：管家页显示全局任务，智能体页显示 Agent 列表，群组页显示群组列表。
- 上侧标题卡片：显示当前对象名称、状态、模型/成员数、连接状态和设置按钮。
- 主体对话卡片：上方为对话消息区，下方为输入区。

点击标题卡片中的设置按钮会打开最上层设置浮层；浮层打开时，底层内容会显示磨砂遮罩。智能体设置、群组设置和管家配置都使用同一套浮层规则。

用户可以在设置页的个人资料中配置昵称和头像。对话气泡中用户消息显示昵称和右侧头像；智能体或群组成员消息显示在左侧。气泡颜色由当前主题控制，默认主题为 Sakura Mint，另有 Executive Workbench 作为工作台主题保留。

新手教程重新打开时，也会使用同一套磨砂浮层和主题化卡片外观。
