## 1. 简介

CoBeing 是一个**多智能体协作平台**。核心理念：

- **Agent** — 拥有独立性格和能力的 AI 助手
- **群组** — 多个 Agent 组队协作完成复杂任务
- **管家** — 内置的管理者，帮你创建 Agent、组建团队

所有数据存储在本地，不需要联网注册，只需要一个 LLM API Key 即可开始。

### 核心能力

```
你
 ├─ 和管家聊天 → 直接完成任务
 ├─ 创建 Agent → 长期使用专业角色
 └─ 组建群组 → 多 Agent 协作
```

## 2. 安装与启动

### 2.1 环境要求

- **Node.js** >= 22.0.0（[下载地址](https://nodejs.org)）
- **pnpm** >= 10.0.0（安装 Node.js 后运行 `npm install -g pnpm`）

### 2.2 首次启动

1. **配置 API Key**

   用文本编辑器打开项目根目录的 `.env` 文件，至少填入一个 LLM 提供商的 Key：

   ```
   DEEPSEEK_API_KEY=your_key_here
   ```

   推荐从 DeepSeek 开始（性价比高）。获取地址：<https://platform.deepseek.com>

2. **双击 `start.bat`**

   首次运行会自动：
   - 安装 pnpm（如果没有）
   - 安装后端依赖
   - 构建后端
   - 安装前端依赖
   - 启动后端服务
   - 打开浏览器访问 GUI

3. **看到聊天界面就说明成功了**

### 2.3 后续启动

直接双击 `start.bat` 即可，跳过已完成的安装步骤。

### 2.4 停止服务

- 关闭浏览器标签页停止前端
- 关闭标题为 "CoBeing Core" 的黑色窗口停止后端

## 4. 和管家对话

管家是你的第一联系人。它不是普通聊天机器人，它能：

### 直接帮你干活

```
你: 帮我写一个 Python 快速排序
管家: （直接输出代码）

你: 当前目录下有什么文件？
管家: （调用工具查看后告诉你）

你: 帮我读一下 config/default.json 的内容
管家: （读取并展示文件内容）
```

### 管理 Agent 和群组

```
你: 帮我创建一个 Python 数据分析专家
管家: 好的，我来帮你创建...

你: 列出所有 Agent
管家: 当前有 2 个 Agent...

你: 创建一个开发团队，包含前端和后端工程师
管家: 好的，我来组建团队...
```

### 管家有什么工具？

| 能力 | 说明 |
|------|------|
| 执行命令 | 运行 Shell 命令 |
| 读写文件 | 查看、创建、编辑文件 |
| 搜索 | 按文件名或内容搜索 |
| 访问网页 | 抓取网页内容 |
| 创建 Agent | 设计并创建新的 Agent |
| 创建群组 | 组建多 Agent 协作团队 |
| 任务分析 | 分析复杂需求并规划方案 |

### 管家的性格

管家说话像一个靠谱的朋友：
- 直接回答，不用"您好请问有什么可以帮您"
- 会有自己的判断，觉得方案不好会直说
- 不确定的时候会说"让我先查一下"

## 5. 创建和管理 Agent

### 5.1 什么时候需要创建 Agent？

**不需要创建 Agent 的情况：**
- 简单的问答、写代码、查资料 → 直接问管家
- 一次性的小任务 → 管家就能搞定

**需要创建 Agent 的情况：**
- 需要一个**长期存在**的专业角色（如"代码审查专家"）
- 管家确实**做不好**的特定领域任务
- 需要和多个专业角色**协作**

### 5.2 创建方式

**方式一：让管家创建（推荐）**

```
你: 帮我创建一个前端开发专家，擅长 React 和 TypeScript
管家: 好的，我来设计这个 Agent...
```

管家会自动设计性格、选择工具、配置权限。

**方式二：通过 GUI 手动创建**

1. 点击侧边栏底部的 **[+ 创建]** 按钮
2. 填写信息：
   - **名称**：Agent 的名字（如 "前端专家"）
   - **角色**：职责描述（如 "React 和 TypeScript 开发"）
   - **Provider**：选择 LLM 提供商
   - **Model**：选择模型
   - **System Prompt**（可选）：自定义行为指令
3. 点击创建

### 5.3 Agent 配置

创建后点击 Agent 进入详情，有两个标签页：

**配置标签页：**

| 配置项 | 说明 |
|--------|------|
| Provider | 使用哪家 LLM（DeepSeek / OpenAI / Anthropic 等） |
| Model | 具体模型（如 deepseek-chat） |
| 权限模式 | full-access / basic-access / workspace-access / workspace-readwrite / read-only |
| 工具列表 | Agent 可以使用的工具 |

**文件标签页：**

查看和编辑 Agent 的性格文件（详见 [Agent 文件系统](#9-agent-文件系统)）

### 5.4 销毁 Agent

在 Agent 详情面板中可以销毁不需要的 Agent，会同时清理相关数据。

## 6. 群组协作

### 6.1 什么是群组？

群组让多个 Agent 在一起协作。比如：

- **开发团队**：前端工程师 + 后端工程师 + 测试工程师
- **内容团队**：写手 + 编辑 + 校对
- **分析团队**：数据分析师 + 可视化专家 + 报告撰写

### 6.2 创建群组

**方式一：让管家创建**

```
你: 创建一个开发团队，需要一个前端工程师和一个后端工程师，一起设计一个 Todo 应用
```

管家会：
1. 如果需要，先创建缺失的 Agent
2. 创建群组并添加成员
3. 启动协作

**方式二：通过 GUI 手动创建**

1. 侧边栏切换到 **Groups** 标签
2. 点击 **[+ 创建]** 按钮
3. 填写群组名称
4. 从现有 Agent 中选择成员
5. 可选填协作主题
6. 点击创建

### 6.3 观看协作

进入群组聊天界面，你可以：

- 实时观看 Agent 之间的讨论
- 看到哪个 Agent 在说什么
- 看到工具调用过程
- 随时发消息参与讨论

### 6.4 群组工作空间

每个群组有独立的工作空间，包含以下文档：

| 文件 | 内容 |
|------|------|
| MEMBERS.md | 成员列表和职责分配 |
| STRUCTURE.md | 项目结构 |
| TASK.md | 任务描述和验收标准 |
| PROGRESS.md | 当前进度 |
| PLAN.md | 任务分工和执行计划 |

在群组详情的 "工作空间" 标签页中查看。

### 6.5 群组如何工作？

```
用户发送消息 / 任务
  ↓
群主收到，分析并分配
  ↓
唤醒相关成员
  ↓
成员之间讨论、执行工具、完成任务
  ↓
群主总结结果
```

## 7. 设置

点击导航栏的 ⚙ 图标进入设置页。

### 7.1 Provider 配置

配置 LLM 提供商的 API Key。在 `.env` 文件中设置：

| Provider | 环境变量 | 推荐模型 |
|----------|----------|----------|
| DeepSeek | `DEEPSEEK_API_KEY` | deepseek-chat |
| Anthropic | `ANTHROPIC_API_KEY` | claude-sonnet-4-20250514 |
| OpenAI | `OPENAI_API_KEY` | gpt-4o |
| Gemini | `GEMINI_API_KEY` | gemini-2.0-flash |
| 智谱 GLM | `ZHIPU_API_KEY` | glm-4 |
| 通义千问 | `QWEN_API_KEY` | qwen-plus |
| MiniMax | `MINIMAX_API_KEY` | — |
| 豆包 | `VOLCENGINE_API_KEY` | — |
| Grok | `XAI_API_KEY` | grok-3 |
| Moonshot | `MOONSHOT_API_KEY` | moonshot-v1 |
| SiliconFlow | `SILICONFLOW_API_KEY` | — |

### 7.2 Channel 配置

配置外部通信渠道，让 Agent 可以在 QQ / Discord / 飞书 / 企业微信 中工作。

| Channel | 说明 |
|---------|------|
| QQ | 通过 NapCat OneBot v11 接入 |
| Discord | 通过 Gateway + REST API 接入 |
| 飞书 | 通过 HTTP Events 接入 |
| 企业微信 | 通过 HTTP 回调接入 |

### 7.3 MCP 服务器

配置外部 MCP 工具服务器，扩展 Agent 的能力。支持：
- **stdio** 模式：启动子进程通信
- **HTTP** 模式：通过 SSE 流式通信

### 7.4 主题

内置多种主题：
- 暗色 / 亮色切换
- 主题配色方案选择

### 7.5 日志

查看系统运行日志，排查问题时有用。

## 8. 技能系统

### 8.1 什么是技能？

技能是预定义的 Prompt 模板，让 Agent 在特定场景下表现更好。Agent 会在需要时自动调用技能。

### 8.2 内置技能

| 技能 | 说明 |
|------|------|
| code-review | 代码审查：质量、安全、性能、最佳实践 |
| project-planning | 项目规划：需求分析、任务分解、风险评估 |
| group-coordination | 群组协调：引导讨论、任务委托、冲突处理 |

### 8.3 技能中心

点击导航栏的 🎯 图标浏览所有可用技能。

### 8.4 给 Agent 分配技能

在创建 Agent 时可以通过 config.json 的 `skills` 字段指定可用技能，管家创建时会自动选择。

## 9. Agent 文件系统

每个 Agent 都有独立的文件目录，位于 `data/agents/{id}/`：

```
data/agents/butler/
├── config.json       ← 运行时配置
├── SOUL.md           ← 性格特质
├── CHARACTER.md      ← 人物描写
├── JOB.md            ← 工作职责
├── USER.md           ← 用户偏好
├── AGENTS.md         ← 工作空间指南
├── EXPERIENCE.md     ← 工作经验
├── TOOLS.md          ← 工具使用策略
└── memory/
    └── YYYY-MM-DD.md ← 每日对话记忆
```

### 各文件说明

| 文件 | 谁写 | 说明 |
|------|------|------|
| **SOUL.md** | Agent 自我更新 | 核心性格：怎么说话、怎么做事、边界在哪 |
| **CHARACTER.md** | Agent 自我更新 | 人物描写：姓名、背景、个性、口癖 |
| **JOB.md** | Agent 自我更新 | 工作职责：擅长什么、怎么判断、怎么工作 |
| **USER.md** | Agent 学习更新 | 关于你的信息：偏好、项目、习惯 |
| **EXPERIENCE.md** | 自动反思写入 | 工作经验：遇到什么问题、怎么解决的 |
| **AGENTS.md** | 框架模板 | 工作空间行为准则 |
| **TOOLS.md** | Agent 自我更新 | 工具使用策略和决策树 |
| **memory/** | 自动写入 | 每日对话原始记录 |

### Agent 会成长

Agent 会在使用过程中自动更新这些文件：
- 你说"你说话太啰嗦了" → Agent 会调整 SOUL.md 的说话风格
- 完成复杂任务后 → 自动总结经验写入 EXPERIENCE.md
- 了解你的偏好 → 更新 USER.md
- 每次对话 → 记录到 memory/ 日记文件

你可以在 GUI 的 "文件" 标签页中查看这些文件的内容变化。

## 10. 配置参考

### 10.1 .env 文件

```bash
# 至少配置一个 Provider 的 Key
DEEPSEEK_API_KEY=sk-xxx

# 可选：配置更多 Provider
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
GEMINI_API_KEY=
ZHIPU_API_KEY=
QWEN_API_KEY=
MINIMAX_API_KEY=
VOLCENGINE_API_KEY=
XAI_API_KEY=
MOONSHOT_API_KEY=
SILICONFLOW_API_KEY=

# QQ 渠道（可选）
QQ_ONEBOT_WS_URL=ws://localhost:3001
QQ_BOT_QQ=

# 系统设置
LOG_LEVEL=info       # debug / info / warn / error
DATA_DIR=./data      # 数据存储目录
```

### 10.2 config/default.json

主配置文件，控制全局行为：

```json
{
  "core": {
    "logLevel": "info",
    "dataDir": "./data",
    "skillsDir": "./skills",
    "promptsDir": "./prompts"
  },
  "agents": ["butler", "host"],
  "providers": { ... },
  "gui": {
    "enabled": true,
    "wsPort": 18765
  }
}
```

### 10.3 Agent config.json

每个 Agent 的独立配置：

```json
{
  "name": "前端专家",
  "role": "React 和 TypeScript 开发",
  "provider": "deepseek",
  "model": "deepseek-chat",
  "permissions": { "mode": "workspace-readwrite" },
  "sandbox": { "enabled": false },
  "tools": ["bash", "read-file", "write-file", "glob", "grep", "web-fetch"],
  "skills": ["code-review"]
}
```

### 10.4 权限模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `full-access` | 无限制 | 管家（默认） |
| `basic-access` | 允许高风险命令 | 高级开发 Agent |
| `workspace-access` | 工作区 + 非破坏性 bash | 普通开发 Agent |
| `workspace-readwrite` | 工作区内可读写 | 普通工作 Agent（默认） |
| `read-only` | 只读，仅安全命令 | 查询/分析类 Agent |

## 11. 常见问题

### Q: 启动后浏览器没打开？

手动打开浏览器访问 http://localhost:1420

### Q: 后端启动报错 "Cannot find module"

```bash
pnpm clean
pnpm build
```

然后重新启动。

### Q: Agent 回复报错

1. 检查 `.env` 中配置的 API Key 是否正确
2. 检查网络连接
3. 查看后端窗口的日志输出

### Q: GUI 连接不上后端

1. 确认后端窗口显示 "WS Server started on port 18765"
2. 等几秒再刷新浏览器
3. 检查 18765 端口是否被其他程序占用

### Q: 如何查看日志？

- 方式一：查看后端黑色窗口的实时输出
- 方式二：GUI 设置页 → 日志

### Q: 如何更换 Agent 使用的模型？

在 GUI 中点击 Agent → 配置标签页 → 修改 Provider 和 Model。

### Q: Agent 创建失败？

1. 确认至少有一个可用的 API Key
2. 尝试用管家创建（管家会自动处理配置）
3. 检查 `data/agents/` 目录是否有写入权限

### Q: 群组里 Agent 不说话？

1. 检查 Agent 是否有可用的 API Key 配置
2. 检查网络连接
3. 尝试手动 @mention 特定 Agent

### Q: 数据存在哪里？

所有数据在项目根目录的 `data/` 文件夹中：
- `data/agents/` — Agent 数据
- `data/groups/` — 群组数据
- `data/butler/` — 管家注册表

### Q: 如何备份数据？

直接复制 `data/` 文件夹即可。
