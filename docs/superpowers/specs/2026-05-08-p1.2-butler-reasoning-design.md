# P1.2 管家多步推理 — 设计文档

> 日期：2026-05-08 | 状态：已确认

## 概述

增强管家（Butler）的推理能力，使其能自主完成多步编排、在对话中主动建议补充角色、按需检查群组进展、感知 Agent 负载状态。

## 设计决策

| 项目 | 方案 |
|------|------|
| 多步推理 | 自动编排 — 管家通过多轮 tool-calling 自主完成全流程 |
| 主动建议 | 对话中自然建议 — 完成复杂任务后评估缺口 |
| 进展跟踪 | 按需检查 — 用户询问时读取群组状态 |
| 负载感知 | 增强 butler-list 输出 — 显示实时状态 |

## 核心架构

采用 **System Prompt 驱动** 方案：butler 已有 ConversationLoop 多轮 tool calling，通过增强 system prompt 引导多步推理，不需要新的编排引擎。

## 改动清单

### 1. System Prompt 增强

在 butler 的 system prompt 开头加入多步推理指南段，替换 `butler-analyze-task` 工具的功能：

- 明确要求面对复杂任务时自主连续调用多个工具
- 定义标准流程：butler-list → 判断 → create-agent/create-group → run-group
- 加入"主动建议"行为准则：完成复杂任务后评估是否需要补充角色

### 2. 删除 butler-analyze-task 工具

该工具是单次 LLM 调用（在工具内部自己调 LLM），功能被 system prompt 取代。保留 `workflow-analyze` / `workflow-plan` 不变（它们是独立的 WorkflowEngine 工具）。

### 3. 增强 butler-list 输出

`makeListTool` 中调用 `agent.getStatus()` 获取每个 Agent 的实时状态，输出格式：

```
Agents:
  - 前端工程师 (frontend-dev) [idle]
  - 后端工程师 (backend-dev) [running]
  - 数据分析师 (data-analyst) [error]
```

### 4. 新增 butler-check-group 工具

```
名称: butler-check-group
参数: groupId (必填)
行为:
  1. 读取群组 workspace PROGRESS.md
  2. 获取群组 TODO 列表（pending/completed 计数）
  3. 返回结构化状态报告
```

### 5. 管家配置更新

`runtime.ts` 中 butler 的 tools 白名单：
- 删除 `"butler-analyze-task"`
- 新增 `"butler-check-group"`

## 文件影响

| 操作 | 文件 | 说明 |
|------|------|------|
| Modify | `packages/core/src/agent/butler.ts` | 删除 makeAnalyzeTaskTool，增强 makeListTool，新增 makeCheckGroupTool |
| Modify | `packages/core/src/runtime.ts` | butler tools 白名单：删除 analyze-task，新增 check-group |

## 构建影响

后端 .ts 变更，需要 `pnpm build`。前端无影响。

## 边界情况

- **无 Agent 时**: butler-list 正常显示空，管家应提示先创建 Agent
- **群组无 PROGRESS.md**: butler-check-group 返回"暂无进展记录"
- **Agent 状态 unknown**: 降级显示 [idle]，不影响功能
- **多步推理中断**: ConversationLoop 的 maxToolRounds 是天然保护，达到上限自动终止
