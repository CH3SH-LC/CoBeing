# P1.3 群组生命周期管理 — 设计文档

> 日期：2026-05-08 | 状态：已确认

## 概述

为群组添加完整生命周期管理：状态机（active → completed → archived）、自动完成检测、硬归档/恢复、工作区文档自动同步。

## 设计决策

| 项目 | 方案 |
|------|------|
| 完成检测 | 基于现有 GroupTodoScanner 60s 轮询，TODO 全完成 + 静默 >1h → 自动标记 completed |
| 归档方式 | 硬归档 — 群组数据打包 zip 到 `data/archives/{id}.zip`，删除原目录 |
| 恢复方式 | 解压 archive zip 回 `data/groups/{id}/`，重建 Group 对象 |
| 文档同步 | Scanner 驱动 — TODO 完成时自动追加 PROGRESS.md |

## 架构

### 1. GroupConfig 类型增强

`packages/shared/src/types.ts` — `GroupConfig` 新增 `status?: 'active' | 'completed' | 'archived'`

### 2. 状态转换

```
active ──(TODO全完成 + 静默>1h)──> completed ──(手动归档)──> archived
  ↑                                      │
  └───(有新TODO)─────────────────────────┘
```

**冻结规则**:
- `completed`: 拒绝新消息（Group.postMessage 返回 error），TODO 只读
- `archived`: 完全冻结，Group 从内存中移除

### 3. Group 类修改

- `postMessage()` 开头检查 `this.config.status`：completed/archived 时拒绝
- 新增 `setStatus(status)` 方法
- 新增 `freeze()` / `unfreeze()` 控制写入

### 4. GroupManager 新方法

- `completeGroup(id)` — 设置 completed + 追加 PROGRESS.md + 广播 WS 通知
- `archiveGroup(id)` — 打包 zip → `data/archives/{id}.zip` → 删除原目录 → 从 Map 移除
- `restoreGroup(id)` — 解压 zip → 重建 Group → 加入 Map → 重新开始 Scanner

### 5. 完成检测增强 (GroupTodoScanner)

`scanOnce()` 末尾增加：

```
const todos = store.list();
const allDone = todos.every(t => t.status === "completed");
if (allDone && todos.length > 0) {
  const lastMsg = groupDb.getAllMessages({ limit: 1 });
  const lastMsgAge = lastMsg.length ? Date.now() - lastMsg[0].timestamp : Infinity;
  if (lastMsgAge > 3600000) {
    groupManager.completeGroup(groupId);
  }
}
```

### 6. 文档同步 (GroupTodoScanner)

`onCompleteAction` 回调中添加：

```
workspace.appendProgress(`${new Date().toISOString().split("T")[0]} TODO "${todo.title}" 已完成`);
```

`completeGroup()` 中追加总结行。

### 7. 前端感知

- 状态变更广播 `group_updated` WS 事件
- 前端侧边栏 `GroupStatusInfo` 新增 `status` 字段，渲染状态标签

## 边界情况

- **空群组（无TODO）**: 不触发完成检测（todos.length > 0 条件）
- **归档后恢复**: 恢复到 active 状态，重新开始 Scanner
- **归档失败**: 保留原数据，不删除，记录错误日志
- **重复归档**: 检查 status 已为 archived，跳过
