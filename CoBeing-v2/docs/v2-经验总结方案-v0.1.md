## 1. 目标

管家（但丁）与工作智能体都要**总结经验**，且经验必须**适合自己**：

1. **沉淀**：管家在归档时总结经验（已存在，增强自适性）；工作智能体在群组归档死亡、长活群组轮次完成时自动总结经验；智能体也可自驱动保存经验。
2. **自适性**（核心）：每次总结以**智能体自身定义**（名字/角色/工具/基座提示/人格）为范围约束——前端智能体总结用户前端偏好，不需要"用户爱吃甜食"（思考2.0 #24 落地）。
3. **执行收敛**（v0.1.1）：信息提取统一由**工具智能体【记忆】**执行——优化内容（自适 scope + 提炼要点 + 条目格式）填充【记忆】的上下文；正常工作智能体不承载"如何总结"的内容，最多在任务完成后被告知"调用【记忆】总结"。
4. **复用**：经验自动注入组装（不只依赖按需 recall），新任务到来即生效。
5. **有界**：条目无限增长 → 画像合并（consolidation）收敛；注入限量，不污染上下文。
6. **容错**：总结/合并失败不阻塞归档、新对话、群组生命周期。

## 2. 现状与差距（2026-08-24 代码事实）

| 面 | 现状 | 差距 |
|---|---|---|
| 存储 | `ExperienceStore` 条目式 md（append/recall/clear） | 无合并/画像；无限增长 |
| 管家总结 | 归档时 LLM 总结写 butler.md（指令通用，不知自身定义） | 不自适；无自动注入 |
| 工作智能体总结 | 无触发时机 | 群组归档不总结成员；长活群组无总结 |
| 自驱动 | call-tool-agent save / 【总结】工具智能体（指令通用） | 范围未知自身定义 |
| 读取 | 仅 call-tool-agent recall（按需） | 组装不注入经验（butler-persona 声称注入但未接线） |

## 3. 总体设计

```
┌──────────────────────────── 触发层 ────────────────────────────┐
│ 管家：归档（阈值/新对话/手动清空）        工作智能体：群组归档死亡 │
│ 工作智能体：长活群组轮次完成（节流）      自驱动：save / invoke   │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────── 统一信息提取入口（kernel.runMemoryAgent）──────┐
│ 全部总结路径 → 工具智能体【记忆】invoke（唯一总结执行者）          │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────── 工具智能体【记忆】上下文（优化内容填充处）──────────┐
│ memoryAgentInstruction(name) =                                   │
│   角色定位（记忆工具智能体）+ 提炼要点（知识/错误/策略/偏好/模式） │
│   + 条目格式（- 开头、≤120 字）+ 自适 scope（自身定义 + 既有画像）│
│ 流程：素材 → LLM 提炼 → 写档案（append）→ 合并检查                │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
┌────────────────────────────── 注入层 ────────────────────────────┐
│ AgentInstance 组装：user 动态区插入 [我的经验档案]                 │
│ （画像 + 最近 N 条；system 前缀保持冻结 → KV 缓存不破坏）          │
│ 工作智能体协议：仅一句「任务完成后调用【记忆】总结」，不注入方法论  │
└───────────────────────────────────────────────────────────────────┘
```

### 3.1 存储（扩展 ExperienceStore，文件形态不变）

`<data>/memory/<name>.md` 条目式 md 不变。条目分两类（按 source 区分）：

| 类型 | source | 语义 | 生命周期 |
|---|---|---|---|
| 画像条目 | `profile` | 合并后的长期稳定经验（用户偏好/领域知识/行为准则/教训） | 每次合并重写（全局唯一） |
| 普通条目 | `main-window-archive` / `main-window-conversation` / `group:<群组名>` / `turn:<群组名>` / 自驱动来源 | 单次沉淀 | 追加；合并时旧条目并入画像 |

新增方法：`loadAll`（全量读取）、`rewrite`（全量重写，合并用）、`count`。

### 3.2 自适范围（ExperienceService.scopeFor，供【记忆】上下文使用）

```
scopeFor(name) =
  名录定义（registry.getAgent：name/role/tools/basePrompt）     ← 工作智能体
  | 但丁人格（BUTLER_PERSONA_PROMPT 职责/纪律）                 ← 管家
  | 未登记实例：名字 + 角色（退化）
  + 既有画像条目内容（"你目前已知的长期经验"）
```

### 3.3 工具智能体【记忆】（v0.1.1 核心变更）

- 内置工具智能体由【总结】更名【记忆】，成为**信息提取统一入口**。
- 【记忆】的上下文（invoke 时的指令）由 `ExperienceService.memoryAgentInstruction(name)` 填充：

```
你是记忆工具智能体【记忆】：审查素材，为下面的智能体提取值得记住的经验，写入其条目式经验档案。
提炼要点：学到了什么知识；犯了什么错误、如何修复；哪些策略有效；
          收到什么用户偏好或反馈；发现了什么新的工作模式或最佳实践。
输出格式：条目化，每条一行、以"- "开头、每条不超过 120 字；无值得保存的经验时输出空。
只总结与该智能体自身职责、能力、用户偏好直接相关的内容（无关知识不总结）。

<scope：自身定义 + 既有画像>
```

- 流程：素材（user）→ LLM 提炼（指令 = memoryAgentInstruction）→ `append(name, {source, content})` → `maybeConsolidate(name)`。
- **正常工作智能体不注入此方法论**——其上下文最多在完成纪律中保留一句「任务完成后调用【记忆】工具智能体总结本次工作」。

### 3.4 合并（有界性）

- 阈值 `EXPERIENCE_MAX_ENTRIES = 50`：追加后条目数 > 阈值 → 合并。
- 合并 = 旧一半普通条目 + 旧画像 → LLM 合并为一条新画像（source=profile）→ `rewrite`（新画像 + 最新一半条目）。
- 失败静默；下次追加重试。

### 3.5 注入（组装）

- `AgentInstanceOptions` 增可选 `experience?: () => Promise<string>`；kernel 为每个实例注入 `experience.contextBlock(name)`。
- `contextBlock(name)` = 画像（≤800 字符）+ 最近 `EXPERIENCE_CONTEXT_ENTRIES = 6` 条（每条 ≤300 字符）。
- 组装位置：user 动态区（`[我的经验档案]` 段，私密内容之后、工具结果之前）→ **system 前缀冻结不变**（KV 缓存保持；对齐 dsh 前缀稳定原则）。
- 工作智能体完成纪律（DEFAULT_PROTOCOL_TEXT）：任务完成后调用【记忆】工具智能体总结本次工作——仅此一句，不携带总结方法论。

### 3.6 触发细则（全部经【记忆】工具智能体）

| 主体 | 时机 | 素材 | source |
|---|---|---|---|
| 管家（主窗口） | 归档（阈值自动/新对话/手动清空） | 公共上下文总结文本 | `main-window-archive` / `main-window-conversation` |
| 工作智能体 | 群组归档死亡（任务边界） | `memberMaterial`：该成员的公共发言 + 私密思考 + 工具调用/结果 | `group:<群组名>` |
| 工作智能体 | 长活群组轮次完成（复用不归档的群组） | `memberMaterial`：自上次总结以来的事件（节流：每 5 轮且有活动才总结，fire-and-forget） | `turn:<群组名>` |
| 任意智能体 | 自驱动：call-tool-agent save / invoke 记忆 | 调用方提供的素材 | 调用方指定 |

### 3.7 与既有机制的关系

- **压缩/归档**：经验总结是归档流程的既有环节（增强自适）；压缩只影响会话内上下文，经验是跨会话长期存储。
- **销毁**：`destroyAgent` 清空经验档案（含画像）不变——"销毁 = 清空所有内容包括记忆"（思考2.0 #3）。
- **名录**：总结范围读取名录定义；未登记实例退化按名字总结。
- **前缀稳定**：经验注入 user 动态区；`request/header` 机制不受影响。
- **责任边界**：ExperienceService 不再直调 LLM 做总结（v0.1.1 起删除 summarize/summarizeScopedText/summarizeGroupMember/summarizeTurn），只提供方法论（memoryAgentInstruction）、素材组装（memberMaterial）、档案管理（注入/合并/信息）。

## 4. 接口

### 4.1 ExperienceService（`packages/core/src/runtime/experience.ts`）

```ts
class ExperienceService {
  constructor(deps: {
    memory: ExperienceStore
    llm: (text: string, instruction: string) => Promise<string>   // 通用 LLM 摘要（网关）
    defOf: (name: string) => { role?: string; tools?: string[]; basePrompt?: string } | undefined
  })
  scopeFor(name: string): Promise<string>              // 自适范围文本
  memoryAgentInstruction(name: string): Promise<string> // 【记忆】完整方法论指令（自适 scope + 提炼要点 + 条目格式）
  contextBlock(name: string): Promise<string>          // 注入文本（画像 + 最近条目；空档案返回 ''）
  consolidate(name: string): Promise<void>             // 画像合并（可独立调用/测试）
  maybeConsolidate(name: string): Promise<void>        // 追加后合并检查
  info(name: string): Promise<{ count: number; lastUpdated?: number }>
}

// 模块级导出：memberMaterial(member, projection, sinceSeq) → 成员素材文本（'' = 无活动）
```

### 4.2 工具智能体【记忆】（`builtin-tool-agents.ts`）

```ts
interface ToolAgentDeps {
  memory: ExperienceStore
  llmSummarize: (text: string, instruction: string) => Promise<string>
  memoryInstruction?: (name: string) => Promise<string>   // 完整方法论（未接线回退通用指令）
  maybeConsolidate?: (name: string) => Promise<void>      // 写档案后合并检查（失败不阻断）
}
// name: '记忆'；invoke({target, material, source}) → 总结 + append + maybeConsolidate
```

### 4.3 AgentInstance（`agent-loop.ts`）

- 选项新增 `experience?: () => Promise<string>`；组装时插入 `[我的经验档案]` 段。
- `DEFAULT_PROTOCOL_TEXT` 完成纪律新增一句「任务完成后调用【记忆】工具智能体总结本次工作」。

### 4.4 Kernel

- 创建 `ExperienceService`（`defOf` = registry.getAgent；butler 特殊 persona）。
- 私有统一入口 `runMemoryAgent(target, material, source)`：调工具智能体【记忆】invoke（全部总结路径共用）。
- butler 实例：`experience: () => service.contextBlock('butler')`；归档总结经 `runMemoryAgent('butler', text, 'main-window-archive')`（ButlerRuntime 的 summarizeArchive 选项语义 = 总结并写档案一体）。
- `makeAgentFor`：工作智能体实例注入 `experience` + `onTurnComplete`（轮次节流总结，经【记忆】）。
- `archiveGroup`：归档前为每个工作智能体成员执行成员总结（memberMaterial → runMemoryAgent，容错）。
- call-tool-agent save / 自驱动接线改为 `runMemoryAgent`。
- 新桥方法 `experience/info`（agent → {count, lastUpdated}）。

## 5. 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `EXPERIENCE_MAX_ENTRIES` | 50 | 触发画像合并的条目数阈值 |
| `EXPERIENCE_CONTEXT_ENTRIES` | 6 | 组装注入的最近条目数 |
| `EXPERIENCE_CONTEXT_PROFILE_CHARS` | 800 | 画像注入上限 |
| `EXPERIENCE_CONTEXT_ENTRY_CHARS` | 300 | 单条注入上限 |
| `EXPERIENCE_TURN_EVERY` | 5 | 长活群组轮次总结节流（0 = 关闭） |
| `EXPERIENCE_MATERIAL_CHARS` | 40_000 | 单次总结素材截断 |

## 6. 边界与权衡

- **成本**：总结 = LLM 调用；管家归档时已有总结（不新增调用）；工作智能体归档总结每群组 ≤ 成员数调用；轮次总结节流。
- **失败容忍**：所有总结/合并路径 catch 静默，不阻塞主流程（归档、新对话、群组生灭照常）。
- **一致性**：经验注入不进事件日志（非"模型可见 ⟺ 已记录"面）——经验是宿主面文件；如需审计可在后续加 experience/write 事件（二期）。
- **冲突**：总结范围受 scope 约束，但 LLM 可能越界——以 scope 指令为软约束，后续可加标签过滤（二期）。
- **执行收敛**（v0.1.1）：单一执行入口（【记忆】）避免方法论散落；工作智能体只负责干活 + 触发，不承载总结能力——与其职责边界一致（纯HI：智能体没有自己的空间，记忆存取交给工具/工具智能体）。
