## 1. 架构总览

### 1.1 分层

```
┌─────────────────────────────────────────────────────┐
│ GUI 层：Tauri 原生桌面（主要入口，独立进程）             │
│   主对话窗口 · 群组窗口 · 智能体管理 · 归档检索 · 通知     │
└──────────────────────┬──────────────────────────────┘
                       │ 本地 IPC/事件流（桥）
┌──────────────────────▼──────────────────────────────┐
│ 内核（宿主面，Node 进程）                              │
│   ├─ 群组运行时：生命周期 · 公共/私密上下文 · mention 队列 │
│   ├─ 智能体运行时：原体循环 · 组装管线 · 忙碌状态机       │
│   ├─ 调度器：工具执行仲裁（排他屏障/并行池/模型序提交）    │
│   ├─ 事件日志：append-only 可重建（权威记录）            │
│   ├─ 插件系统：注册皆 effect · 热重载 · 隔离            │
│   ├─ 权限与安全：最小权限 · 文件观测 CAS · 沙箱          │
│   └─ 模型路由：provider 适配器 · 网关（队列/限流/重试）   │
└──────┬──────────────────┬──────────────────┬─────────┘
       │                  │                  │
  数据层               子进程             外部能力
  data/           持久 shell（每实例）   MCP server / 工具智能体
                  工具智能体进程
```

### 1.2 设计原则（dsh 机制 → v2 映射）

| dsh 机制 | v2 对应 |
|---|---|
| Model-visible ⟺ logged（请求可从日志重建） | 所有到达模型请求的输入 = 事件日志可重建；invariant 校验器独立重建请求 |
| 插件失败结束当前 turn，不终止 loop | 单智能体实例的插件/工具失败只结束当前工作段，不拖垮群组与内核 |
| 注册皆 effect（ctx.effect/ctx.on，HMR 安全） | 插件系统全部注册返回 disposer，卸载自动清理 |
| 调度器（排他屏障/有界并行池/模型序提交/abort 合成） | 内核调度器原样移植（§3） |
| HMR = 卸载+加载，fiber epoch 级联依赖方 | 插件热重载：配置/代码变更不重启内核，替换提供方级联重建依赖方 |
| 崩溃隔离（fiber 级）+ 子进程兜底 | 进程内错误边界 + 工具智能体/持久 shell/MCP 独立进程，崩溃可重启 |
| 冻结 persona + 前缀稳定缓存 | 原体三段冻结系统提示（原体规格 §2） |
| session-persistence（JSONL/SQLite、写游标、冷修复） | 群组/主窗口事件日志持久化（§2.3） |
| fs-observation-policy（版本守卫 CAS） | 群组空间文件观测策略（read 记版本，write/edit 校验） |

## 2. 可重建事件日志（核心）

### 2.1 事件模型

- **一条权威事件流**：每个窗口（主对话窗口、每个群组）一条 append-only 事件日志。
- 事件类型（v0.1 草案）：
  - `speak`：公共上下文发言（含 mention 数组、附任务说明）
  - `think`：私密内容追加（智能体思考、工具过程，不进入公共视图）
  - `tool/call` + `tool/result`：工具调用与结果（含合成 ABORTED 结果）
  - `assistant/complete`：一次模型调用成功完成的锚点（记录组装内容 + 使用量）
  - `group/lifecycle`：创建/复用/归档/死亡
  - `agent/status`：实例状态（idle/busy）、忙碌 flag 排队
  - `butler/relay`：群组内管家 → 主窗口管家的工具消息
  - `request/header`：每次请求的有效配置记录（供重建与审计）
- **硬性约定：模型可见 ⟺ 已记录**——任何进入模型请求的输入必须能从日志重建；新增模型可见输入必须新增事件类型。

### 2.2 重建语义

- 崩溃恢复只作用于**冷窗口**（无活跃会话）：加载日志 → 校验 → 重建投影（消息列表、上下文、状态）。
- 活跃窗口崩溃不适用：内存权威日志 + 写游标，恢复时绝不重 append 已存储事件。
- 组装管线从日志派生产出（投影），不另存一份"当前上下文"作为真相源。

### 2.3 持久化

- 每窗口一条 **JSONL 日志**（`data/group/<name>/log.jsonl`、`data/butler/log.jsonl`），追加写 + 原子落盘（临时文件 + rename）。
- 名录/状态类数据进 **SQLite 数据库**（`data/registry.db`）：智能体名录、群组名录、状态索引。
- 经验档案 = 条目式纯文档 md（`data/memory/<agentName>.md`，已定稿）。
- 群组空间 = 普通文件（`data/group/<name>/`），工作产物与日志同目录。

## 3. 调度器（工具执行与群组并发仲裁）

照搬 dsh `tool-calls.ts` 语义，作为内核服务：

1. **分类**：每个工具调用先 `prepare`，按执行模式分类——`dispatch`（可并行）/ `post-result` / `final-result`。
2. **排他屏障**：排他调用（独占资源、依赖比较）形成屏障，前后并行池必须排干。
3. **有界并行池**：并行安全调用进入滚动池（`maxParallelToolCalls`，默认 10；1 = 串行）。群组内单实例内并行有界。
4. **模型序提交**：结果按模型调用顺序提交（committed 只推进连续槽位），策略/结果/上下文保持模型序；仅派发与执行体可重叠。
5. **abort 收敛**：取消 = 停止新派发 + 排干已启动 + 未派发调用写合成 `ABORTED_BEFORE_DISPATCH` 错误结果——日志永远完整、可重放。
6. **调度器失败**：停止新派发、等待已启动派发、到达 turn 错误边界，**不虚构工具结果**。

**群组级仲裁**（v2 特有，叠加在调度器之上）：
- **公共上下文写入**：`speak` 事件追加必须原子（内核单点序列化）；逻辑顺序 = 事件日志顺序。
- **mention 唤醒队列**：每群组每实例一个 FIFO；忙碌 flag=true 时新 mention 排队，工作完成（turn 收敛）后处理下一条。
- **文件写冲突**：文件观测策略（§8）——read 返回版本，write/edit 带 baseVersion 校验，不一致拒绝。

## 4. 插件化与隔离（技术基调核心）

### 4.1 插件模型

- **一切皆插件**：核心只保留——事件日志、调度器、群组/智能体运行时骨架、权限底座、模型路由网关。其余能力（搜索、web、技能、MCP 桥、工具智能体实现、GUI 数据服务）全部插件化。
- **注册皆 effect**：每个注册（工具、事件监听、服务提供）都绑定所属插件 fiber，卸载即自动清理；注册表 `register()` 返回 disposer。
- 插件形态：内置（内核同进程）+ 外部（`data/plugins/`，独立加载单元）。

### 4.2 热重载

- **配置热重载**：配置文件（含插件启停、参数）变更 → 事务式重组合 → 不重启内核；失败保留最后一个可用树并广播错误。
- **代码热重载（开发态）**：文件变更 → 卸载旧插件 + 加载新插件（fiber 替换）；fiber 激活 epoch 串联服务提供方 uid，替换提供方自动级联重建依赖方。
- **运行中会话不受扰**：热重载不关闭活跃群组/主窗口的进行中工作（活跃前缀接管）；进行中的模型请求保留原适配器注册（防混用）。

### 4.3 崩溃隔离（"一个插件崩溃不影响全局"）

- **进程内错误边界**：插件/工具失败只结束当前 turn（单实例工作段），异常不扩散到内核与其他实例；错误被记录并转为可恢复状态。
- **子进程隔离（兜底）**：持久 shell（每群组实例一个 PTY 子进程）、工具智能体、MCP server 运行在独立子进程——崩溃只影响所属实例/能力，可自动重启；恢复后日志不丢失（事件已落盘）。

## 5. 上下文组装管线

- **组装公式**（原体规格 §4.1）：`冻结系统提示 + 群组公共上下文 + 私密上下文 + 最近工具结果 + 按需记忆`。
- **前缀稳定**：冻结提示与公共上下文是请求前缀（append-only、字节稳定 → KV 缓存命中）；私密内容追加在最新位置（发言之前），只影响后缀。
- **管家主窗口**：每 100k token 触发"归档记忆（【总结】→ 写档案）→ 压缩上下文"；手动清空同流程。
- **全量压缩流程**（公共超长）：【总结】按各独立上下文总结每个智能体 → 【压缩】分别压缩公共/各智能体上下文 → 压缩事件写入日志（可重建）→ 管家重新开启工作（防停摆）。压缩是日志中的**替换事件**（旧节点被遮蔽），重建依赖压缩事件而非原始文本。

## 6. 数据层

```
<程序注册位置>/data/
├── registry.db              # 名录数据库（SQLite）：智能体名录/群组名录/状态/权限
├── butler/                  # 主窗口管家：log.jsonl · 经验档案 md · 人格文件（只读权限）
├── group/<群组名>/          # 群组空间：工作文件 · log.jsonl · meta.json
├── memory/<agentName>.md    # 经验档案（条目式纯文档，按名字全局共享）
├── archive/<群组名>/        # 归档（群组死亡后冻结：日志+工作文件快照+索引）
├── plugins/                 # 外部插件
└── config/                  # 配置文件（热重载）
```

- 名录数据库职责：智能体/群组登记、实例状态、权限记录；管家创建/销毁工具的副职责 = 编辑它。
- 归档 = 只读快照 + 索引条目（供 GUI 检索，检索方案待设计）。

## 7. 运行时状态机

### 7.1 群组

```
创建（管家工具+用户批准，label≥3）→ 工作（mention 驱动）→ [复用：连续任务]
→ 完成报告 → 用户验收 → 用户告知成功 → 归档（只读快照）→ 死亡
     ↑ 失败：找原因 → 无解通知用户（可管家转发）
```

### 7.2 智能体实例（原体）

```
idle → (被 mention 唤醒，flag=true) → 组装 → 思考/工具循环 → 发言/报告完成 → flag=false → idle
```

### 7.3 管家（双实例）

- 主窗口管家：长期上下文 + 人格 + 100k 归档压缩 + 中转/管理工具 + 只读。
- 群组内管家：组装同工作智能体；被 mention → 分析 → `butler-relay` 工具消息 → 主窗口管家被唤醒 → 回复用户。

## 8. 权限与安全

- **默认最小权限**：实例只能读写所属群组空间 + 自己的记忆调取；跨目录访问一律拒绝。
- **全量访问群组**（"无"）：受限特例，需明确需求，创建时强确认。
- **管家只读**：管家对一切文件只读（工具集不含写）。
- **文件观测策略（CAS）**：read 返回版本戳（mtime+size），write/edit 必须携带 baseVersion，不一致拒绝并提示重读——防多实例静默覆写。
- **命令安全**：persistent-bash 在群组空间内执行；命令风险分级（危险命令拒绝/需确认），可选沙箱。
- **权限附加**：管家可为群组内每个智能体附加细化权限（读写/工具白名单），记录在名录数据库。

## 9. GUI 接口面（Tauri 原生）

- 进程：Tauri 前端（独立进程）↔ 内核（Node）经本地 IPC + 事件流桥（通信协议待前端调研定稿）。
- 必需界面（规格 §9）：主对话窗口、群组窗口（label/成员/发言/任务说明展示）、智能体管理（名录/创建/销毁确认）、归档检索、通知（任务栏闪烁 + 一声滴）。
- 只读呈现：GUI 是内核事件的投影，不持有业务真相源。
