现在我们构建这个程序的使用场景

主要使用方式：用户直接和管家对话。管家进一步把用户需求进行总结、分析、转发，提供给具体工作的智能体或者群组。具体工作的智能体或群组工作过程中可以随时向用户提问，这个提问由管家进行转述给用户。

其它使用方式：用户直接进入群组，以用户的身份进行发言，直接跟群组内的智能体对话



群组：

所有对话窗口都是群组而不是一对一，所有对话窗口的label都大于等于3

其中，user代表用户，拥有最高权限

bulter代表管家，权限仅次于用户

大量的工作智能体参与群组工作

通过具体工具mention进行唤醒，mention [name]表示唤醒对象，为数组可唤醒多人。

若mention user，则有给用户的提示，仅存在于用户已经直接参与上下文的群组或者信息不适合由bulter转发

若mention bulter，则唤醒群组内的管家，管家此时必须进行分析，回传给主对话窗口并返回给用户。

关于唤醒，所有唤醒由智能体自己决定，或者用户手动mention。

智能体需要有角色意识，考虑自己的角色，自己适合完成的工作部分，是否需要别的智能体协助，涉及协助，则自己需要产出什么，预留什么接口与别人对接，别人需要完成什么。

群组的寿命由工作决定，一项任务完成则群组死亡，所有信息归档。一项新任务则创建一个新群组。

群组由群组空间，群组成员，群组窗口组成

群组空间指群组工作的地方，可以指定位置、采用默认位置的一个新子文件夹、或无（可以访问一切地方）

群组成员是工作智能体+user+bulter

工作智能体个人成长和具体任务分离，个人成长总结在自己的个人文件夹内，在任何群组内自己都对这个文件夹有访问能力，具体工作全部在群组空间内完成

群组的上下文窗口分公共上下文和独立上下文，维护统一的对话列表，智能体可以通过工具在列表内发言，所有发言按时间顺序（真实为逻辑顺序）作为公共上下文，智能体工作产生的思考、自己的产出等全部是自己的私密内容不需要被别人知道，独立上下文为公共上下文+私密内容，在组装独立上下文的时候放在对应的自己发言前面。智能体上传的上下文为自己的独立上下文



管家：

管家是用户工作的主入口

管家的上下文组织为超过预定长度则先总结归档，再压缩。用户可以手动清空上下文，在这之前，会先总结归档再清空

管家自己不完成任何具体工作，承担两项功能：与用户聊天和作为用户和具体工作的中转

管家是唯一需要人格化的智能体，与用户对话的过程中仅需要模拟一个真实角色即可

管家的中转任务分为两个方向。从用户到群组，转述用户的含义给群组内的工作智能体，同时需要mention对应的智能体开启工作；从群组到用户，转述工作智能体的需求，让用户说得更清楚

在核心任务之外，还有创造/毁灭智能体，创造/毁灭群组的职能。创造任务无需批准，毁灭任务则需要用户明确的点击确认



经验：

所有长久存活的智能体都需要总结经验

管家的经验总结在自己的目录

工作智能体的经历和经验总结在自己的目录，并非群组空间

通过调用总结这个工具智能体进行总结

不要吝啬总结，所有智能体都需要不断进化才能更好用



工具智能体：

部分固定操作不可硬编码，需要LLM参与，但是工作内容又非常固定，这时需要工具智能体

智能体像调用工具一样调用工具智能体

目前唯一的工具智能体是总结智能体，帮助总结经验和记忆
