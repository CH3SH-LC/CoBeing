## 0. v2 自动配对（2.0.4）：零配置互联

> 解决 v1 手动流程的痛点：不再需要手动复制地址 + Token 到手机。**电脑开机即广播自身，手机一键发现 → 确认 → 自动交换密钥 → 自动构建公网隧道**。

### 0.1 使用流程

1. **电脑**：启动 CoBeing 桌面端（内核默认 `--remote-port 0 --remote-host 0.0.0.0 --auto-tunnel`，即自动开启远程 WS + 局域网发现 + 配对后自动隧道）。
2. **手机**：打开 App → 设置 → **扫描局域网电脑**（UDP 广播，同一 WiFi）。
3. 发现电脑 → 点击「配对」（= 手机确认）→ 手机发出 `pair/request` → 电脑生成并返回密钥（token）+ 连接信息。
4. 手机自动保存配置并连接；**电脑同时自动启动 cloudflared quick tunnel**，URL 就绪后经已建立的 WS notify 推送给手机，手机保存为公网候补地址。
5. 之后手机**自动在局域网/公网间切换**：同一 WiFi 走直连；出门在外断线后自动尝试公网隧道（同一把 token）。

### 0.2 协议扩展

| 项 | 内容 |
|---|---|
| 发现协议 | `cobeing-discover/1`（UDP，端口 7844）——手机广播 `{v:1,type:"scan"}` → 电脑单播应答 `{v:1,type:"announce",protocol,id,name,version,wsPort,host,lanUrl}`；电脑另每 30s 主动广播 announce |
| 配对方法 | WS 未鉴权阶段 `pair/request {deviceId, deviceName}` → `{token, server:{name,version,dataRoot,lanUrl,protocol}}`（同连接不再自动鉴权，客户端用 token 重连走标准 auth） |
| 配对持久化 | `<dataRoot>/remote.pairs.json`（deviceId/deviceName/pairedAt；重启保留；GUI「手机连接」可撤销） |
| 隧道自动管理 | `TunnelManager`（Node 直接管理 cloudflared 子进程）：探测 PATH → `tools/cloudflared.exe` → 缺失自动下载；`tunnel --url http://127.0.0.1:<port> --no-autoupdate --protocol http2`；日志抓取 trycloudflare URL → notify `{type:'tunnel',action:'update',url}` |
| 状态查询 | 桥方法 `remote/status`（GUI「手机连接」条目）：`{enabled,port,lanUrl,discoveryPort,tunnelUrl,tunnelRunning,pairs,token}`；`pair/revoke {deviceId}` 撤销配对 |
| 手机候补地址 | Profile 增 `tunnelUrl`；`connect(url, token, [tunnelUrl])` 断线重连时轮转交替尝试（局域网 ↔ 公网自动切换） |

### 0.3 手机端原生插件

`LanDiscoveryPlugin.java`（Capacitor 自定义插件，MainActivity 注册）：DatagramSocket 广播 scan 到 `255.255.255.255:7844` + `WifiManager.MulticastLock`（Android 默认过滤广播帧）→ 收集 announce 应答（去重，4s 超时）→ 返回设备列表。Manifest 新增 `ACCESS_WIFI_STATE` + `CHANGE_WIFI_MULTICAST_STATE`。

### 0.4 安全说明

- 配对无鉴权（仅限局域网内），等同 v1 手动复制 token 的安全等级；**拿到 token 即可控制电脑**（与 v1 一致）。
- 手机确认是唯一门禁；电脑 GUI「手机连接」可见配对记录并可随时撤销。
- 快速缓解：撤销配对 + 更换 token（删除 `remote.token` 重启内核）。

### 0.5 已知问题与处置

1. **代理 TUN 环境（实测：OneLite 等 fake-ip 模式）会劫持 cloudflared**：隧道可注册成功（拿到 URL）但数据面回连失败（502/530），或本机 wss 直连 TLS 断开。处置：代理软件规则放行 `cloudflared.exe` 与 `*.trycloudflare.com` / `*.argotunnel.com` 直连，或临时关闭 TUN；`verify-pair.mjs --with-tunnel` 会自动检测 fake-ip 网卡并提示。
2. **quick tunnel URL 每次电脑重启变化**：手机与电脑同一 WiFi 时打开 App 自动同步新地址（notify 推送）；异地且电脑重启后需重新同步一次。长期稳定可配 named tunnel（§5 Named Tunnel）。
3. **发现端口 7844 被占用**：内核降级为仅 WS（不阻断配对？不——无发现则手机扫不到；GUI「手机连接」显示未启用，需释放端口）。

## 1. 目标

1. 手机端 app（Android APK）：在任何地方直接控制电脑上的 CoBeing——对话、群组、智能体、远程操作。
2. 插件扩展：**服务器驱动面板**——内核侧注册控制面板（manifest 描述控件），app 泛化渲染；新增控制能力不需要发版更新 app。
3. 外网互联：基于 cloudflared 的隧道，手机与电脑不同局域网也可互联；**双向通讯不阻塞**（全双工 WebSocket：双方可同时发请求/通知，无轮询）。

## 2. 总体架构

```
┌─────────────┐   wss://xxxx.trycloudflare.com   ┌──────────────┐   https   ┌──────────────┐
│ 手机 app     │ ◄═════════════════════════════► │ Cloudflare   │ ◄═══════ │ 电脑          │
│ (Capacitor)  │   JSON-RPC 2.0 over WebSocket    │  边缘/隧道    │          │ cloudflared  │
└─────────────┘                                  └──────────────┘          │   ↓ ws://127.0.0.1:7843
                                                                           │  cobeing-kernel --remote-port
                                                                           └──────────────┘
   局域网模式：手机直接连 ws://<电脑IP>:7843（同一 WiFi，不经 cloudflared）
```

- **复用内核桥协议**：`BridgeServer` 是 transport 无关的（`send/onLine` 接口）。WS 远程传输 = 给同一个 `BridgeServer` 换一个 WebSocket transport，桌面 GUI 的 23 个既有方法全部天然可用。
- **双向不阻塞**：WebSocket 全双工 + JSON-RPC 请求/通知对发。手机 → 电脑：请求（发消息/控制）。电脑 → 手机：notify 通知（管家提示/确认请求/任务完成），服务端连接建立即发 `hello`。
- **鉴权**：token。连接后第一消息必须是 `auth {token}`，未鉴权前其他方法一律 `-32001`。token 持久化在 `<dataRoot>/remote.token`（首次生成），CLI 启动时加载；也可 `--remote-token` 显式指定。

## 3. WS 传输契约（cobeing-ws/1）

- 地址：`ws://<host>:<port>/`（外网 `wss://<tunnel-url>/`）。默认端口 `7843`。
- 帧：每帧一个 JSON-RPC 2.0 消息（与 stdio 行协议完全一致的 shape）。
- 连接流程：
  1. 服务端收到连接，客户端首帧发送 `{jsonrpc:'2.0', id:1, method:'auth', params:{token}}`。
  2. 服务端校验：成功 → 发 `hello` 通知 `{jsonrpc:'2.0', method:'notify', params:{type:'hello', server:{name, version, dataRoot, agentCount}}}`；失败 → 响应 `{id:1, error:{code:-32001, message:'unauthorized'}}`，连接保留但所有非 auth 请求均被拒。
  3. 鉴权后所有方法（含新 `remote.*`）直接进 BridgeServer 路由。
- 错误码：`-32700` 解析失败 / `-32601` 方法不存在 / `-32602` 参数错误 / `-32000` 业务错误 / `-32001` 未鉴权。
- 心跳：应用层 `ping` 方法；30s 无消息客户端主动 ping，60s 无任何帧服务端断开（`ws` 包心跳）。
- 服务端 → 客户端主动消息：仅 `notify`（与 CLI stdout 通知同 shape：`{type:'text'|'confirm'|'hello', ...}`）。

## 4. 远程控制方法（remote.*，BridgeServer 新增路由）

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `remote/info` | – | `{name,version,dataRoot,roots,agentCount,platform}` | 服务器信息 |
| `remote/panels` | – | `PanelManifest[]` | 控制面板 manifest（插件面） |
| `remote/invoke` | `{panel, action, params?}` | `unknown` | 执行面板动作 |
| `remote/screenshot` | – | `{mime:'image/png', base64}` | 全屏截屏（PowerShell CopyFromScreen） |
| `remote/clipboard` | `{op:'get'\|'set', text?}` | `{text}` | 剪贴板读取/写入 |
| `remote/media` | `{op:'volumeUp'\|'volumeDown'\|'mute'\|'playPause'}` | `null` | 媒体键（keybd_event P/Invoke） |
| `remote/power` | `{op:'lock'\|'sleep'}` | `null` | 锁屏/睡眠（MVP 不含关机，安全） |
| `remote/roots` | – | `string[]` | 允许的文件根（默认 `<dataRoot>`；CLI `--remote-root` 可追加） |
| `remote/listFiles` | `{root, path}` | `{root,path,entries:[{name,isDir,size,mtime}]}` | 目录浏览（根逃逸拒绝） |
| `remote/download` | `{root, path}` | `{name,size,mime?,base64}` | 文件下载（限 20MB） |
| `remote/upload` | `{root, path, name, base64}` | `{path,size}` | 文件上传（限 20MB） |

### 面板 manifest（插件扩展面）

```ts
interface PanelManifest {
  id: string            // 如 'quick'
  name: string          // 如 '快捷控制'
  icon?: string         // emoji 或图标名
  sections: {
    title: string
    controls: Control[]
  }[]
}
type Control =
  | { type: 'button'; id: string; label: string; icon?: string; confirm?: string }  // confirm=二次确认文案
  | { type: 'toggle'; id: string; label: string; value: boolean }
  | { type: 'input';  id: string; label: string; placeholder?: string }
  | { type: 'display'; id: string; label: string; value?: string }
```

- 控件 → 动作映射在**内核侧**实现（面板注册器：`panel/action → handler(params)`）。
- app 只做泛化渲染：按钮/开关/输入框 → `remote/invoke`；display 值随 `remote/invoke` 结果或 notify 刷新。
- **新增控制能力 = 内核侧注册新面板/动作，app 无需发版**。这就是"极强的插件扩展能力"的落地形态（配合内核工具/工具智能体插件体系，面板动作可调用任意内核服务）。
- 内置面板 v1：`quick`（截屏/锁屏/睡眠/媒体播放暂停/音量±/静音/剪贴板取/剪贴板送）。文件浏览为独立视图（见 §6），后续可作为 `files` 面板扩展。

## 5. cloudflared 三层递进

| 模式 | 命令 | 适用 | 说明 |
|---|---|---|---|
| LAN 直连 | `scripts/remote.ps1 -Mode lan` | 同一 WiFi | 手机连 `ws://<电脑IP>:7843`，零公网；脚本自动绑定 `0.0.0.0`（token 鉴权兜底）+ 尝试自动加防火墙放行规则（失败打印手动命令） |
| Quick Tunnel | `scripts/remote.ps1 -Mode tunnel` | 临时外网验证 | `cloudflared tunnel --url http://127.0.0.1:7843`（**--protocol http2**：QUIC/UDP 在部分国内网络/本地代理 fake-ip 环境被丢弃，TCP 更稳）→ `https://<随机>.trycloudflare.com`（WSS 自动）；URL 每次变；仅绑 127.0.0.1 更安全 |
| Named Tunnel | 文档步骤 | 长期使用 | 免费域名 + `cloudflared tunnel create/login/route dns`，URL 稳定；可加 Cloudflare Access 二次防护 |

- cloudflared 安装：`scripts/remote.ps1` 自动探测/下载 `tools/cloudflared.exe`（winget 可选）。
- **连接信息提取**：启动完成后地址+Token 打印在屏幕底部高亮区块（cloudflared 日志重定向不刷屏，隧道 URL 自动抓取），并落盘 `<data>\remote.info.txt`（记事本打开即可复制）。
- 安全基线：token 必选（不设 token 拒绝启动 remote）；quick tunnel URL 随机不可枚举；named tunnel 建议开启 Cloudflare Access（免费额度）或至少保持 token。
- 双向不阻塞的验证路径：隧道 E2E 脚本直连 trycloudflare URL 发 `ping`/`remote/info`/`mainWindowSpeak`，确认外网通路 + WSS + 全双工。

### Named Tunnel（长期稳定 URL，可选进阶）

1. 登录并创建隧道（首次一次性）：
   ```
   tools\cloudflared.exe tunnel login                      # 浏览器授权，选择域名
   tools\cloudflared.exe tunnel create cobeing            # 生成隧道凭据
   tools\cloudflared.exe tunnel route dns cobeing <你的域名>.example.com
   ```
2. 配置 `~/.cloudflared/config.yml`：
   ```yaml
   tunnel: cobeing
   credentials-file: C:\Users\<你>\.cloudflared\<隧道ID>.json
   ingress:
     - hostname: cobeing.example.com
       service: http://127.0.0.1:7843
     - service: http_status:404
   ```
3. 启动（与内核同机）：`tools\cloudflared.exe tunnel run cobeing`
4. 手机 App 填 `https://cobeing.example.com`（自动 wss）+ token。
5. 可选加固：Cloudflare Zero Trust → Access 添加该域名应用（免费 50 用户额度），要求手机端通过 Access 认证后再进 WS；App 侧后续版本支持 Access JWT 头。

### ⚠️ 国内网络已知问题（实测发现）

**运营商 DNS 可能屏蔽 `*.trycloudflare.com` 通配域**（本机实测：系统默认 DNS 返回 NXDOMAIN，而 223.5.5.5（阿里）/ 1.1.1.1 解析正常）。影响：电脑或手机连不上 quick tunnel 域名（cloudflared 本身不受影响，隧道正常注册）。

处置：
1. **首选**：把电脑和手机的 DNS 改为 `223.5.5.5`（阿里）或 `114.114.114.114`（114）——WiFi 设置里改即可，App 无需改动；
2. 或使用 named tunnel + 自有域名（不走 trycloudflare 域名，国内解析正常）；
3. 验证脚本 `scripts/verify-tunnel.mjs` 已内置 DoH 回退（阿里 223.5.5.5 → 1.1.1.1 解析 IP + SNI/Host 直连），即使本机 DNS 被污染也能完成外网全链路验证。

## 6. 手机端 app（mobile/，Capacitor 6 + React 19 + Vite）

- 工程独立（不进 pnpm workspace，避免污染根 typecheck/测试）。`npx cap add android` 生成 Android 工程，`gradlew assembleDebug` 产出 APK（appId `com.cobeing.mobile`，名称 CoBeing）。
- **使用三步**：① 电脑端运行 `scripts/remote.ps1 -Mode lan`（同 WiFi）或 `-Mode tunnel`（外网），记下地址 + token；② 手机 App「设置」→ 添加服务器（名称/地址/token，可保存多配置，局域网与外网并存）；③ 点连接，顶部状态胶囊变绿即就绪。
- **六视图 + 底部 Tab（对话/群组/智能体/控制台/设置）**：
  1. 连接管理（设置页）：多配置（名称/URL/token）本地保存，当前配置切换；顶部状态胶囊（绿=已连/黄=重连中/红=断开）。
  2. 对话：但丁主窗口投影（气泡列表）+ 发送 + 新对话窗口 + 会话列表切换（当前/历史）。
  3. 群组：群列表 → 群投影 → 发言（mention chips + 任务说明）。
  4. 智能体：名录 + 创建向导 + 待批准队列（确认/拒绝——手机端即可批准建智能体）。
  5. 控制台：`remote/panels` 泛化渲染 + 快捷动作。
  6. 文件（控制台页内二级视图）：`remote/roots` 根浏览 → 列表 → 下载（系统分享/保存）+ 上传（文件选择 → base64）。
- 通知：notify 事件 → 应用内横幅 + 震动（`navigator.vibrate`）；`confirm` 类型渲染可点击确认卡（点击后 `mainWindowSpeak` 回传「【确认答复】label」——与桌面 GUI 同协议）。
- 重连：指数退避（1s→2s→4s…上限 30s），断线自动重连，连接期间请求队列挂起/失败重试（幂等 ping 外不自动重试）。
- 主题：复用桌面樱花薄荷糖果色 token，移动端适配（触控目标 ≥44px，底部 Tab ≥56px）。
- 测试：rpc 客户端（fake WebSocket 注入）+ 视图冒烟（jsdom）。
