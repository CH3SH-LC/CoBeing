# CoBeing v2 模型错误码清单

> 版本：2026-08-29（v2.0.7）
> 定位：模型调用错误的统一分类与排查指引。所有模型相关错误以 `LLM_<类别>` 错误码呈现，
> 用户可见位置：对话/群组内的 `[工作失败]` 发言、桌面端通知横幅、手机端通知/投影、内核日志（request/error 事件）。

---

## 1. 设计原则（v2.0.7 起）

- **取消 mock 静默回退**：未配置 API Key / 智能体无 provider 时**不再返回 "(mock) 收到" 硬回复**，而是明确报错（LLM_CONFIG_MISSING / LLM_NO_ADAPTER）。
- mock 仅作为**显式测试选项**保留（GUI 创建智能体时显式选择 provider=mock，并黄色警示"不会真实工作"）。
- 所有失败经 `[工作失败] <错误码>：中文说明` 发布到对话/群组投影（GUI 与手机端都可见），并落盘 `request/error` 事件（含错误链与诊断 detail）。

## 2. 错误码总表

| 错误码 | 含义 | 典型场景 | 用户处置 |
|---|---|---|---|
| `LLM_CONFIG_MISSING` | 未配置模型服务 | 无 API Key；智能体没指定 provider 且内核无默认 | 设置 → 模型 添加来源（或 DEEPSEEK_API_KEY 环境变量），重启 |
| `LLM_NO_ADAPTER` | provider 未注册 | 名录里写了 deepseek 但内核启动时无 key | 配置 API Key 后重启 |
| `LLM_NETWORK` | 网络不可达 | DNS 解析失败 / 连接被拒 / TLS 异常 / 代理拦截 | 检查网络与代理；Base URL 是否正确 |
| `LLM_TIMEOUT` | 请求超时 | 模型服务慢 / 网络差 | 稍后重试；检查网络 |
| `LLM_API_401` | 鉴权失败 | API Key 无效/过期 | 检查/更换 API Key |
| `LLM_API_402` | 余额不足 | DeepSeek 账户欠费 | 前往模型服务商充值 |
| `LLM_API_404` | 地址不存在 | Base URL 填错 | 检查 Base URL（默认 https://api.deepseek.com） |
| `LLM_API_429` | 限流 | 请求过于频繁 | 稍后重试 |
| `LLM_API_5XX` | 服务端错误 | DeepSeek 服务异常 | 稍后重试 |
| `LLM_MODEL_NOT_FOUND` | 模型不存在 | 模型名拼错/该模型不可用 | 检查模型名（设置 → 模型） |
| `LLM_CONTEXT_OVERFLOW` | 上下文超长 | 对话过长 | 新对话 / 等待自动压缩 |
| `LLM_EMPTY_RESPONSE` | 空回复 | **推理模型（deepseek-v4-flash）思考后未输出正式内容**（content 空、reasoning_content 有值）或响应截断 | 工具调用任务改用 deepseek-chat；或增大 maxTokens |
| `LLM_RETRIES_EXHAUSTED` | 重试耗尽 | 网关重试 3 次后仍失败（保留原始错误 detail） | 按 detail 定位；稍后重试 |

## 3. 错误在哪些环节出现

| 环节 | 呈现方式 |
|---|---|
| 内核启动（无 key） | stderr `[model] 未配置...` + notify 文本（桌面横幅/手机 toast）「[模型] ⚠ ...」 |
| 主窗口但丁对话 | 投影内 `[工作失败] LLM_xxx：...` 发言（GUI 对话气泡 / 手机端对话页可见） |
| 群组智能体工作 | 群组投影 `[工作失败]` 发言（mention butler 转述）+ 群组页可见 |
| 经验总结/记忆/诚实 | 调用失败被各环节容错（不阻塞主流程），内核日志 request/error 可查 |
| 桌面「设置 → 模型」 | **「测试连接」按钮**：真实调用模型 API 验证来源（ok/message/status），免去对话试错 |
| 手机端 | 经投影与 notify 自动可见，无单独界面 |

## 4. 排查指引（按症状）

1. **对话回复 `LLM_CONFIG_MISSING`** → 设置 → 模型 → 确认有来源且「当前使用」已选；或环境变量 DEEPSEEK_API_KEY；保存后**重启应用**。
2. **回复 `LLM_API_401`** → API Key 无效；点「测试连接」确认。
3. **回复 `LLM_EMPTY_RESPONSE`（deepseek-v4-flash）** → 该模型是推理模型（先思考后回答），工具调用/短回复场景易空；改用 `deepseek-chat`（设置 → 模型 → 模型名改为 deepseek-chat，或创建智能体时选 deepseek-chat）。
4. **`LLM_NETWORK`** → 本机代理（Clash 类 TUN）可能拦截 api.deepseek.com；放行或临时关闭；测试连接可复现。
5. **想确认配置是否有效** → 设置 → 模型 → 对应来源点「测试连接」：绿=可用；红=给出原因（鉴权/余额/地址/网络）。

## 5. 实现位置

- 错误定义与分类：`packages/core/src/llm/errors.ts`
- DeepSeek 适配器错误分类（HTTP 状态/网络/空内容）：`packages/core/src/llm/deepseek.ts`
- 网关 provider 缺失/超时/重试耗尽：`packages/core/src/llm/gateway.ts`
- 智能体默认模型路由（取消 mock 回退）：`packages/core/src/runtime/agent-loop.ts` + `packages/core/src/kernel.ts`
- 生产装配（无 key 启动提示）：`packages/bridge/src/cli.ts`
- 测试连接命令：`gui/src-tauri/src/model_config.rs`（test_model_source）
- 真实验证：`scripts/verify-model-errors.mjs`（A 无 key / B 坏 key / C 好 key / D 工作智能体默认继承）、`scripts/verify-model-config.mjs`（5 场景）
