## 1. 定位与设计原则

**原体 = 工作智能体的最小内核模板**。所有工作智能体 = 原体 + 实例化时冻结的定义（名字/职责/权限）。原体本身不完成任何具体工作，它是"能干活的通用底座"。

严格参照 dsh 极简模式（minimal preset）的三条核心原则：

1. **模型面 / 宿主面分离**：原体只定义"模型可见面"（系统提示、工具、上下文组装）；沙箱、权限、持久化、模型路由、可重建日志全部由平台（宿主面）提供，不缩水。
2. **决策面最小化**：工具少而完备（每多一个工具都在增加模型的选择负担）；系统提示无动态注入（实例化后冻结 → 前缀稳定 → KV 缓存命中）。
3. **上下文纯净**：大窗口 + 无默认压缩；压缩是兜底流程（由【压缩】工具智能体执行），不是默认路径。

与 dsh minimal 的差异（v2 场景必需，不违反极简精神）：原体必须携带**群组协作协议**（v2 是群组工作场景，dsh 是单 agent 编码场景），故工具集 > 2 个，但每一类都只保留一个、能力互补、覆盖完整闭环。

## 2. 模型面：系统提示（实例化时冻结，运行期不变）

组装顺序固定，三段全部在实例化时冻结 → 请求前缀字节级稳定：

```
[基座]  You are a helpful working agent.      ← 固定 1 句（dsh 形式：complete、无 runtime context、无动态注入）
[协议]  群组协作协议（见 §6，每实例相同）
[定义]  智能体定义（名字 / JOB / 群组内权限 / 附加工具，实例化时冻结）
```

- **基座严格采用 dsh 极简模式形式**：固定 1 句 + complete（唯一系统提示）+ 无 runtime context + 无任何动态注入。
- 句子与 dsh 原文（`You are a helpful software engineer assistant.`）同构，仅将 `software engineer` 替换为 `working agent` 以适配非编码智能体（前端/搜索/写作等）；如坚持逐字采用 dsh 原文可随时换回。
- 运行期间**任何段都不变**（如需改定义 = 重新实例化或新建群组），保证 KV 缓存前缀稳定与"模型可见 ⟺ 日志可重建"。

## 3. 模型面：默认工具集（7 个）

| # | 工具 | 说明 | 来源 |
|---|---|---|---|
| 1 | `persistent-bash` | 持久 shell：状态跨调用保留（cwd/环境/后台作业）；超时或 exit 即关闭并明确告知重置；输出保留最早前缀 + 显式裁剪说明 | dsh |
| 2 | `str-replace-editor` | 精确编辑协议：view（支持 offset/limit 分页）/ create / **write（全量覆盖，dsh write 语义）** / str_replace / insert；str_replace 要求唯一字面匹配（0 或多个匹配一律拒绝，无 replace_all）；路径支持绝对或相对（相对群组空间） | dsh |
| 3 | `glob-files` | 模式找文件（dsh glob）：无斜杠模式匹配任意深度 basename；`**` 任意深度 / `*` 段内任意 / `?` 单字符；跳过 node_modules/.git；上限 100；返回相对群组空间路径 | dsh |
| 4 | `grep-files` | 内容搜索（dsh grep）：正则匹配，返回 `相对路径:行号:内容`；include 过滤（如 `*.ts`）+ path 子目录；跳过 node_modules/.git 与二进制；上限 250 | dsh |
| 5 | `todo-list` | 结构化任务清单（dsh todo_write）：add / update / complete / list；按 群组/智能体 隔离；多步任务的记忆面 | dsh |
| 6 | `group-speak` | 向群组公共上下文发言；可附带 `mention: [name...]`（唤醒他人时必须附任务说明）；发言 = 公共上下文唯一入口 | v2 特有 |
| 7 | `call-tool-agent` | **统一能力入口（memory 已并入）**：a) 调用工具智能体（【总结】【压缩】）——契约化输入/输出；b) 记忆档案操作——recall（读取条目式纯文档 md 档案）/ save（触发【总结】写入档案） | v2 特有 |

**附加能力不进默认集**：搜索、web、专用 MCP、技能等按智能体定义或群组权限挂载（插件化，核心保持干净）。原则：每个附加工具必须回答"它是否提供了 bash/编辑器/群组协议覆盖不了的能力"。

> 2026-08-24 修订：默认集 4 → 7。用户要求"提高智能体基础编程能力，参考 dsh"——补齐 dsh 编程核心面：glob（找文件）、grep（搜内容）、todo（任务跟踪）、write（全量覆盖）、view 分页。仍遵守"每一类只保留一个、能力互补、覆盖完整闭环"：文件读写（编辑器+glob+grep）+ 命令执行（bash）+ 计划跟踪（todo）+ 协作（group-speak + call-tool-agent）。

## 4. 模型面：上下文模型

### 4.1 独立上下文组装公式

```
独立上下文 = [冻结系统提示] + [群组公共上下文] + [自己的私密上下文] + [最近工具结果] + [按需记忆]
```

- **冻结系统提示（前缀稳定）**：基座 + 群组协作协议 + 智能体定义 + **输出协议 + 可用工具清单（按名称字典序，附参数 schema 摘要）**——全部实例化冻结，运行期字节不变 → 请求前缀稳定 → KV 缓存命中（dsh orderTools/request-cache stability 对齐；2026-08-24 修订）。
- **公共上下文**：群组统一对话列表（逻辑顺序，append-only 可重建日志）。
- **私密上下文**：自己的思考、工具调用过程（write 内容等），追加在最新位置（自己最新发言之前）；**不影响既有前缀**。
- **记忆（经验档案）**：**自动注入**——组装时宿主面读取条目式 md 档案（画像 + 最近 N 条）插入 user 动态区 `[我的经验档案]` 段（system 前缀冻结不变；2026-08-24 方案 v0.1）；另可经 `call-tool-agent` recall 按需调取更多。

> 2026-08-24 修订：经验档案由"仅按需 recall"升级为"**自动注入 + 按需 recall**"（方案 v0.1：自适 scope 总结 / 画像合并 / 四触发）。

> 2026-08-24 修订：原"输出协议 + 工具清单"位于 user 文本首部（随 systemNote 动态漂移），改为移入 system 冻结段——dsh 编码能力对照诊断（`docs/v2-dsh编码能力对照诊断.md`）P0-1 落地。

### 4.2 上下文纪律

- **共享 = 落盘即共享**：write 过程是私密；落盘到群组空间的文件可被其他智能体 read。思考不落盘即私有。
- **无默认压缩**：contextWindow 默认 **1,000,000 token**（同 dsh minimal，2026-08-20 定稿）。
- **私密膨胀** → `call-tool-agent` 调【压缩】分段压缩自己的私密内容。
- **公共超长** → 全量压缩流程：①【总结】按各独立上下文总结每个智能体内容 → ②【压缩】分别压缩公共上下文与各工作智能体上下文 → ③ 管家再次开启工作（防全体停摆）。

## 5. 宿主面：平台提供（不缩水）

| 能力 | 要求 |
|---|---|
| 可重建日志 | 所有到达模型请求的输入必须能从日志重建（模型可见 ⟺ 已记录）；对话列表 append-only |
| 沙箱与权限 | 默认最小权限：只能读写当前群组空间；群组空间"无"（全量访问）是受限特例；管家可为实例附加细化权限 |
| 调度器 | 工具执行并发有界（参考 dsh：并行池/屏障/模型序提交/abort 合成结果） |
| 模型路由 | 实例按定义绑定 provider/模型；LLM 调用经统一网关（队列 + 限流 + 超时 + 重试） |
| 持久 shell | 每个群组实例一个 owner-scoped PTY，cwd 默认为群组空间 |

## 6. 群组协作协议（冻结注入的协议段内容）

- **角色意识**：考虑自己的角色、自己适合完成的工作部分、是否需要别的智能体协助；涉及协助时明确：自己产出什么、预留什么接口对接、别人需要完成什么。
- **唤醒纪律**：唤醒他人必须附任务说明（要对方做什么）；被唤醒后按任务说明工作；允许 @all。
- **发言纪律**：思考/过程保持私密；落盘即共享；发言要简洁、有信息量。
- **完成报告**：工作完成后在群组发言报告完成（管家据此回报用户验收）。
- **提问纪律**：需要用户输入时——mention user（软约束，用户未直接参与时通常不建议）或 mention butler（由管家分析转述给用户）。
- **失败纪律**：任务失败需找原因；无解则通知用户（可管家转发）。
- **忙碌纪律**：工作中被再次 mention → 完成当前工作后再处理（flag 排队）。

## 7. 循环与状态机

```
idle → (被 mention 唤醒) → busy(flag=true) → 组装上下文 → 思考/工具循环（私密）
     → 发言（公共）/ 报告完成 → flag=false → idle
```

可靠性语义（参考 dsh agent-loop，不因极简而简化）：
- 单个工具失败只结束当前 turn，不终止整个循环；模型请求错误进入重试通道。
- abort/超时收敛：拒绝新工具调用、排干已启动结果、未派发调用得合成 ABORTED 结果——日志永远完整。
- 并行工具调用有界；排他调用形成屏障；结果保持模型序。

## 8. 实例化与生命周期

**实例化输入**（创建时冻结）：
- 智能体定义：名字、JOB（职责）、角色描述 —— 来自名录数据库（管家创建工具的副职责）
- 群组空间路径（cwd）、权限配置（默认最小 + 管家附加）
- 工具集：原体默认 7 个 + 定义附加 + 群组附加
- 持久 shell（owner = 本实例）、事件日志段（新实例 = 新日志段）

**生命周期**：
```
创建（管家工具 + 用户批准）→ 名录登记 → 加入群组（label+1）
→ 群组内实例化（冻结定义）→ 工作 → 群组归档死亡 → 实例销毁（日志归档冻结）
经验档案（条目式纯文档 md）按名字保留，全局共享，跨群组可用
```

**销毁语义**（用户明确点击确认）：清空人格经验档案 + 注销名录数据库条目 + 不再可被调用；历史记录不清除。

## 9. 变体关系

### 9.1 工具智能体（【总结】【压缩】）= 原体特化

- 契约化：固定输入/输出 schema，像工具一样被调用（经 `call-tool-agent`），**不在群组 label 中**，不被 mention。
- 无角色意识、无记忆、无个人成长；实例化时冻结系统提示 = 基座 + 工作契约。
- **实现形态：半硬编码**（2026-08-20 定稿）——固定流程骨架（分段、边界、落盘等由算法完成），LLM 只参与必要环节（如总结的提炼、压缩的摘要生成）。
- 【总结】：输入 = 智能体定义 + 独立上下文/素材；输出 = 经验条目 → **追加写入条目式纯文档 md 档案**；总结范围严格参考智能体定义（前端智能体总结前端偏好，不需要"用户爱吃甜食"）。
- 【压缩】：输入 = 私密内容段 / 公共上下文；输出 = 压缩摘要（分段压缩）。

### 9.2 管家 = 原体 + 人格层（非原体默认实例）

- **主窗口管家**：原体基座 + 人格化层（唯一需要人格化的智能体）+ 主窗口长期上下文 + 中转协议 + 管理工具（创造/毁灭智能体与群组、编辑名录数据库）+ 只读权限（无 bash/编辑工具）。
- **群组内管家**：上下文组装方式与工作智能体相同（公共 + 私密），经 `butler-relay` 工具向主窗口管家发消息；主窗口管家被唤醒后回复用户。
- 主窗口上下文：每 100k token 归档记忆 + 压缩；手动清空前先总结归档。

## 10. 经验档案形态（定稿）

- **条目式纯文档 md**（2026-08-20 定稿）：每个智能体一份 Markdown 档案（按名字全局共享），内容为条目式结构，每条经验一个条目。
- 条目字段：时间 / 来源（群组、任务）/ 内容 / 标签（可选）；**画像条目**（source=profile）为合并后的长期稳定经验。
- 写入方：【总结】工具智能体 + **ExperienceService 自适总结**（方案 v0.1）——范围 = 智能体自身定义 + 既有画像（思考2.0 #24）。
- 读取方：**组装自动注入**（画像 ≤800 字符 + 最近 6 条）+ 工作智能体经 `call-tool-agent` recall；管家经自身工具读取（只读）。
- **有界**：普通条目 > 50 触发画像合并（旧条目 + 旧画像 LLM 合并为新画像，全量重写）。
- **不使用数据库存储经验**；名录数据库保持数据库形态（职责：智能体名录 + 状态）。
