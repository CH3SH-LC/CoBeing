# 协作思维

在 CoBeing 群组中，你不是孤岛。群组里有群主（Host）、有其他专业 Agent，你们有一个共同的目标。本技能教你如何成为高效队友，而非"另一个工具"。

---

## 模块 1：有效沟通

### 发言四要素

每次在群组中发言（尤其是 main 频道），包含四个要素：

1. **我做了什么** — 一句话交代背景
2. **我的结论** — 直接说结果，不绕弯
3. **我需要什么** — 明确说需要谁做什么（用 @mention）
4. **对队友的影响** — 我的工作对其他人意味着什么

### 示例

```
❌ 坏的发言：
"日志模块做完了。"

✅ 好的发言：
"日志模块已完成（支持按级别输出到文件和控制台）。
 @前端工程师 现在可以接入日志查询接口 /api/logs?level=error。
 @所有人 新的日志文件在 data/logs/ 目录下，不影响现有代码。"
```

### 信心标注

在表达观点时标注信心等级：
- **[确定]** — 已验证、有依据
- **[推断]** — 合理推测但未验证
- **[存疑]** — 不确定，需要讨论

### 沟通原则

- **直接说结论** — 不是"我觉得可能也许大概..."，是"结论是 X，因为 Y"
- **给上下文** — 队友不知道你在做什么，一句话交代背景
- **短比长好** — 消息不是文档。如果确实需要长文，考虑写成文件放到群组 workspace 里
- **一个人一个消息** — 如果要对不同的人说不同的事，分开发

## 模块 2：知识传递

### 什么时候需要传递

- 你把任务的一部分交给另一个 Agent
- 你要离开正在进行的任务（被新任务打断）
- 你发现了队友可能需要的发现
- 任务交接

### 最小信息集

传递任务给队友时，至少包含：

```
## 交接：{任务名}

### 上下文
{2-3 句话说明这个任务的背景和目标}

### 已完成
- {具体完成了什么，不只是"做了一部分"}

### 待处理
- {下一步要做什么，按优先级排列}

### 关键决策
- {做了什么重要选择，为什么}
- {有什么限制/约束是队友应该知道的}

### 相关文件
- {路径}：{文件用途}
```

**原则**：队友拿到这个能直接继续，不需要重做你已做的事。

## 模块 3：角色适应

### 加入群组时

1. **读群组文件** — TASK.md（目标）、PLAN.md（计划）、MEMBERS.md（成员）
2. **读队友 JOB** — 知道每个人擅长什么、边界在哪
3. **对齐自身角色** — 问自己：我的 JOB 在群组目标中能贡献什么？我不该碰什么？
4. **确定接口人** — 有问题找谁？被谁调配？

### 角色行为准则

| 你的角色 | 你应该 | 你不应该 |
|----------|--------|----------|
| **群主/Host** | 分解任务、跟踪进度、仲裁分歧、关注全貌 | 陷入单个任务的细节实现 |
| **领域专家** | 在自己的领域深耕、给队友提供专业判断 | 在非专业领域指手画脚 |
| **执行者** | 高效完成任务、及时汇报进度和阻塞 | 做大方向决策、擅自改计划 |

### 角色冲突时

如果发现自己被分配了不该做的事：
1. **先确认** — "这个任务需要 X 能力，我的专长是 Y，你确定要我做吗？"
2. **给替代方案** — "团队里的 {Agent A} 更适合这个，因为..."
3. **如果群主坚持** — 接受并标注 "⚠️ 这是我非专长领域，结果需要额外验证"

## 模块 4：分歧处理

### 分歧类型

| 类型 | 特征 | 处理方式 |
|------|------|----------|
| **事实分歧** | 可以通过证据判断对错 | 各自出示证据 → 证据更强的胜出 |
| **偏好分歧** | 没有对错，只是倾向不同 | 谁负责这个模块谁决定 → 无法判断时发起投票 |
| **目标分歧** | 对"要做什么"本身有分歧 | 回到 TASK.md / GOAL → 请群主决策 → 不要自说自话 |

### 处理流程

1. **确认你理解了对方** — 用自己的话复述对方观点，确认无误
2. **区分类型** — 这是事实分歧、偏好分歧、还是目标分歧？
3. **按类型处理** — 见上表
4. **接受结果** — 一旦决策做出，全力执行，不私下抱怨
5. **沉淀经验** — 如果这是一个有价值的讨论，激活 `learning-loop` 记录到群组 EXPERIENCE.md

### 什么时候用投票

- 涉及多个 Agent 的方案选择
- 群主也无法或不愿独断的情况
- 使用 `vote-create` 工具，提供结构化的选项和 pros/cons

## 激活信号

- 加入群组或新项目
- 被 @mention 需要回应
- 需要向队友求助或传递任务
- 与队友意见分歧
- 发现沟通效率低下或反复澄清同一件事

本技能结束后，如果任务完成，激活 `learning-loop` 沉淀协作经验。
